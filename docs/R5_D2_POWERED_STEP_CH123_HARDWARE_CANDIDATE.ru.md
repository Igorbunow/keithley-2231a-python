# R5-D2 — аппаратная квалификация native STEP CH1/CH2/CH3, подготовка

**Результат настоящего изменения:** реализован квалификационный runner и независимый анализатор исходного JSONL. Все его программные проверки выполняются без открытия оборудования. **Новые реальные тесты НЕ ПРОВЕДЕНЫ; `HW NOT_RUN` для CH2/CH3.** Запуск под нагрузкой требует отдельного согласования схемы, пределов и явного разрешения оператора.

## Различие между поддержкой прибора и доказательствами

Нативные `VOLT:STEP`, `VOLT:UP`, `VOLT:DOWN`, `CURR:STEP`, `CURR:UP`, `CURR:DOWN` маршрутизируются драйвером по выбранному `INST:NSEL` каналу. R5-D1 снял искусственную CH1-привязку у защищённого квалификационного контекста. Это **не** автоматически подтверждает поведение SCPI под реальной нагрузкой на CH2/CH3. Изменять `hardware_evidence` в capabilities можно только после просмотра оригинальных аппаратных журналов.

## Порядок квалификации

1. Отдельно выполняются недостающие **OFF-only VOLT STEP** на CH2 и CH3 стандартным `tools/r4_5_step_mutation_qualify.py` (по одному случаю на запуск). На клеммах нет ни KEL103, ни диода, ни DMM, ни перемычек; все каналы OFF. Статус изменения регистров — **цифровой**, не силовой.
2. Для каждого выбранного канала отдельно допускается **CV**: уставка 3,30 В, лимит 0,150 А, KEL103 CR 40 Ω, DMM7510 FRONT DCV параллельно выбранному выходу. Проверяются пять аналоговых точек и четыре STEP перехода **+10/+10/−10/−10 мВ**. MAX 0,60 Вт — ограничение квалификационного опыта, не предел канала прибора.
3. Отдельным запуском и физическим подтверждением **CC**: уставка 3,30 В, лимит 0,100 А, KEL103 CR 11 Ω, DMM7510 FRONT DCV параллельно выбранному выходу. Четыре перехода **+5/+5/−5/−5 мА**, пять аналоговых точек. Выходы остальных каналов должны оставаться OFF, клеммы пустыми.
4. После **каждого** случая — цифровое подтверждение OFF CH1/CH2/CH3, KEL INPUT OFF, затем физическое подтверждение. Ни автоматического перехода к следующему каналу/режиму, ни повторов при ошибке.
5. Только потом отдельным инструментом аудитируются **оригинальные** JSONL: модель/прошивка, provenance, операторские gates, wire SCPI, ошибки, выбранный канал, `STEP`-регистры, `UP/UP/DOWN/DOWN`, пять показаний DMM, KEL и PSU, аналоговые дельты и OFF. `REVIEWABLE_PASS_NOT_AUTOMATIC_QUALIFICATION` требует окончательного инженерного просмотра.

## Переподключение относительно опыта ВАХ

Для STEP-проверки нельзя оставлять схему «диод + 99,86 Ω» вместо электронной нагрузки. **Только после физического OFF**: убрать диод/балласт из силовой цепи, подключить выбранный CHx +/− к соответствующим входам KEL103 +/−, а DMM7510 FRONT DCV HI/LO — параллельно этому же выбранному выходу. Вход DMM `AMPS` остаётся пустым; другие выходы БП не соединены ни между собой, ни с нагрузкой. Проверить токовую/мощностную способность проводов, правильность полярности, отсутствие внешнего питания и перемычек Series/Parallel/Tracking. KEL103 INPUT OFF до разрешения начала. Нельзя переключать цепь при включённом выходе.

## Команды только dry-run (сейчас)

```bash
python3 tools/r5_d2_step_powered_qualify.py --config config/bench.local.toml --channel 2 --mode cv
python3 tools/r5_d2_step_powered_qualify.py --config config/bench.local.toml --channel 2 --mode cc
python3 tools/r5_d2_step_powered_qualify.py --config config/bench.local.toml --channel 3 --mode cv
python3 tools/r5_d2_step_powered_qualify.py --config config/bench.local.toml --channel 3 --mode cc
```

Ни одна из этих команд без `--execute` не открывает порты. Встроенные защиты: ручные подтверждения bench/hash, начальной схемы, отдельного POWER и финального OFF; запрет запуска с `bench.example.toml`, без интерактивной TTY, при неразрешённых адаптерах/тайм-аутах; только `CHAN:OUTP 1` выбранного канала, только однократное включение, 1 запись STEP, 4 изменения, запрещены reset/trigger/групповой ON. Независимые PSU/KEL/DMM показания регистрируются хронологически, **не синхронно**. Потеря связи означает UNKNOWN, а не успешное отключение; программный checkpoint **не заменяет внешнюю аппаратную защиту**.

После отдельно согласованного аппаратного опыта аудитор запускается офлайн:

```bash
python3 tools/audit_r5_d2_step_powered.py /path/to/original/events.jsonl
```

Никакие физические проверки, статусы в capabilities и подтверждение `HW PASS` **не изменены данным патчем**.
