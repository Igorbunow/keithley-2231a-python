# R3.5.26 — единый последовательный запуск H10

## Семантика CLI

| Команда | Подгруппы | Результат |
| --- | --- | --- |
| `python3 tools/hw_qualify.py preflight H10 --config config/bench.local.toml` | Карточки OFF + low-current + high-current | Только вывод, никакого I/O |
| `python3 tools/hw_qualify.py run H10 --config config/bench.local.toml --dry-run` | Те же три карточки | Только вывод, никакого I/O |
| `python3 tools/hw_qualify.py run H10 --config config/bench.local.toml --execute` | **OFF → CV/CC low-current → CV3A/CC4A high-current** | 0 лишь при всех трёх подтверждённых подгруппах; иначе 2 и STOP |
| `python3 tools/hw_qualify.py run H10 --off-only --config config/bench.local.toml --execute` | Только OFF-диагностика | Изолированная команда возвращает 0 при успешной OFF-диагностике; её evidence продолжает содержать `PARTIAL`, потому что силовые режимы не проверялись |
| `python3 tools/hw_qualify.py run H10 --powered --config config/bench.local.toml --execute` | Только low-current CV/CC | Отдельный gated-прогон |
| `python3 tools/hw_qualify.py run H10 --high-current --config config/bench.local.toml --execute` | Только CV3A/CC4A | Отдельный gated-прогон, до ~4 А |

`--off-only`, `--powered`, `--high-current` взаимно исключаются в H10. Семантика H09 без флагов **не меняется**.

## Реальная последовательность full

1. Общий токен **плана** полного запуска (сам по себе не разрешает включение). Без интерактивного TTY запуск запрещён.
2. **OFF**: клеммы свободны, перемычки/нагрузка/DMM отключены. Повторная проверка USB адаптера PSU, отдельные токены bench и OFF-схемы. Выключенные выходы при переключении Independent ↔ Parallel. Выход из Parallel, Independent, контроль OFF, подтверждение оператором физического OFF. Сохранение evidence. `PARTIAL` в этой подгруппе является ожидаемым *scope*, а не ошибкой.
3. Только если OFF завершился штатно, сохранённые события подтверждают источник/конфигурацию, отсутствие OUTP ON, переходы Parallel и итоговый Independent, перейти к **low-current**. Оператор при OFF собирает параллельные перемычки, KEL103 CR30/CR5 и DMM7510; новые bench/схемные подтверждения. Подача питания на две отдельные CV/CC точки с собственными дисплейными подтверждениями и **PSU+KEL OFF между точками**. Завершение: PSU+KEL OFF, оператор физически отсоединяет KEL/DMM/обе перемычки, Independent и OFF проверены. Отдельный evidence со статусом PASS обязателен.
4. Только после полного PASS low-current, перейти к **high-current**. Снова при OFF подключить подходящие AWG10-перемычки и KEL103 AWG10, DMM; новые bench/схемные подтверждения. CV3A при CR1Ω (~3В, ~3А, ~9Вт), затем отдельный PSU OFF + KEL INPUT OFF, CC4A при CR0.5Ω (~2В, 4А, ~8Вт); измерительный порог 10Вт. По окончании — PSU+KEL OFF, физическое снятие перемычек/нагрузки/DMM, Independent и OFF. Отдельный PASS обязателен.
5. Сохранить **четыре** независимых файла событий: три субпрогона плюс отдельный `H10_FULL` summary, в котором привязаны исходный source SHA, SHA стенда, названия подгрупп, фактические результаты и пути до журналов. Полный H10 PASS **не означает** автоматической записи статуса HW VERIFIED в матрицу.

## Fail-closed условия

- Любой неверный токен, невозможность открыть порт, неисправность транспорта, неизвестное состояние OFF, SCPI-ошибка, промежуточная ошибка измерения, неполный evidence, ненулевой код подпрохода или изменение SHA между подпроходами — STOP, без следующих включений и без автоматического повторного запуска. Если OFF не подтверждён, безопасное отключение вручную; не переставлять перемычки под напряжением.
- Aggregate verifier независимо проверяет для каждого подпрохода **ровно по одному** `metadata`, `bench_configuration`, `query_outcome`, `outcome`, совпадение исходных SHA, статус и физический OFF. OFF-диагностика обязана показать Parallel 1 → 0, итоговый Independent snapshot, отсутствие OUTP ON. Силовые этапы обязаны показать подтверждённый `topology_restore=VERIFIED_INDEPENDENT`, физический `disconnect_parallel_wiring`, **ровно два** `OUTP 1` с промежуточным `OUTP 0`, по четыре выборки и подтверждение дисплея каждого CV/CC в верном порядке.
- Драйвер, ограничители мощности/тока, допуски измерений, политики SCPI, `finish_combined_powered()` и токены отдельных этапов **не изменяются**. Между подпроходами создаётся новая управляемая сессия; небезопасная или потерявшая связь сессия не повторяется.
- Аппаратный предел пары по напряжению не доказан: 4В и 10Вт — **software/measured limits**, не аппаратные OVP/мгновенная защита. Индивидуальное распределение тока CH1/CH2 не измеряется. CH3 физически оставить открытым.
