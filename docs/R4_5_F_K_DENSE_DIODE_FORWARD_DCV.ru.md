# R4.5-F-K — итоговый пример прямой ВАХ диода 1N4933

Статус: **только программная подготовка; аппаратный опыт НЕ выполнен**. Не включать прибор до отдельного подтверждения оператора. R4.5-F-J.3 CH1/CH2/CH3 (по 2 точки с PSU readback) завершён как профильный **пример**, не как калибровка. Источник данных: `channel_1.csv`, `channel_2.csv`, `channel_3.csv`, `completed.json` — SHA-256 подтверждены. Три канала CV, цифровой/операторский OFF положительны. В CSV всё ещё только диагностический ток PSU, поэтому по ним нельзя заявить точность ВАХ.

## Граница программной архитектуры

- `src/keithley2231a/` **не изменён**. Библиотека предоставляет только аппаратные операции, считывание и safeguards.
- `examples/iv_profile.py` выбирает `current_source: ballast_dcv` без `force` для прямого напряжения на диоде. Если DMM-DCV observer отсутствует, сценарий отклоняется ДО любого обращения к прибору. Никакого fallback на `PSU_READBACK`.
- `examples/iv_sweep.py` добавляет ограниченный **хостовый** checkpoint `max_powered_s`, который НЕ является автономным watchdog. Единственный способ защиты от отказа связи — независимое аппаратное отключение оператором; при UNKNOWN запрещены повторы команд.
- `examples/diode_iv.py` берет `U_DMM` через инъецированный observer и рассчитывает `I=(U_PSU_readback-U_DMM_diode)/99.86`, сохраняя исходные PSU DCV, PSU DCI, DMM DCV, источник измерения и статус `UNQUALIFIED`.
- `tools/r4_5_1n4933_dense_dcv.py` использует уже существующий тестовый адаптер DMM7510 и bench-config, не добавляет DMM-код в PSU-драйвер. Он принимает только фиксированную одноканальную конфигурацию.
- `tools/r4_5_1n4933_dense_plot.py` без доступа к приборам проверяет CSV + SHA-256 + `completed.json`, строит SVG и JSON с предупреждениями о форме/гистерезисе.

## Схема и границы

Только CH1 (CH2/CH3 **OFF**, физически пустые). CH1+ → резистор **99,86 Ом**, ≥0,25 Вт → анод 1N4933 → катод (полоска) → CH1−. DMM7510 FRONT INPUT HI на анод, FRONT INPUT LO на катод, DCV диапазон 10 В. **AMPS пустой**; последовательную схему DCI полностью убрать. KEL103 не подключён; Series/Parallel/Tracking и перемычки отсутствуют, других источников питания нет. Приборы не соединяются друг с другом по силовым выходам.

Одна серия: CH1 **0,60 → 1,20 В** с шагом **0,02 В** (31 точка), затем **1,18 → 0,60 В** с шагом **−0,02 В** (30 точек), итого **61 точка**, без смены полярности диода и без перекоммутации под напряжением. Лимит тока CH1 0,020 А, суммарная аппаратно допустимая мощность при коротком диоде — 1,20²/99,86≈0,0144 Вт, ниже рейтинга резистора. При коротком диоде ток ≤12,02 мА за счет резистора. Хостовый checkpoint 240 с; **не независимая аппаратная защита**. Внутри одного прохода смена уставки не является аппаратным триггером, и измерения DMM и PSU идут последовательно.

**Это только прямая ветвь ВАХ.** Противоположная полярность требует отдельной схемы и не входит в этап. Источник не является SMU и не измеряет напряжение непосредственно на выводах диода. В расчет входит точность readback напряжения 2231A: на паспортных условиях 25±5 °C порядка **±(0,06% показания + 20 мВ)**. Уже фиксированное слагаемое 20 мВ даёт около ±0,200 мА при 99,86 Ом. Погрешности DMM, резистора, проводников и асинхронность сюда НЕ включены. Даже гладкая кривая не будет автоматической калибровкой, и в итогах запрещено заявлять измерительную точность 0,1 мА. Профиль допускает 0,5 мА как требование к диагностике, но НЕ подтверждает его метрологически; значения ниже нижней границы паспортной неопределённости напряжения отклоняются заранее.

## Команды только программной проверки

```bash
PYTHONPATH=src:tests:tests/hardware:. python3 -m unittest discover -s tests -q
python3 -m compileall -q src tests tools experiments examples
python3 tools/r4_5_1n4933_dense_dcv.py --config config/bench.local.toml
PYTHONPATH=src python3 examples/diode_iv.py --profile examples/diode_iv_ch1_dense_dcv_profile.json
```

В CLI `examples/diode_iv.py --run` **намеренно запрещён** для этого профиля без DMM observer. Исполнение — только через специально ограниченный инструмент после независимого согласования схемы, каждого разрешения и проверки программных тестов.

## Аппаратный кандидат — НЕ запускать до отдельного согласования

```bash
python3 tools/r4_5_1n4933_dense_dcv.py \
  --config config/bench.local.toml \
  --output-dir reports/hardware/R45FK_DENSE_CH1_20261031 \
  --execute
```

`--execute` открывает оба прибора, спрашивает bench SHA и физическую топологию, проверяет все выходы OFF и отключённую Series/Parallel/Tracking, конфигурирует DMM7510 FRONT DCV с автоматическим контролем SCPI-ошибок, проверяет OFF baseline, требует разрешений перед CH1 и финальное подтверждение OFF. Механизм `emergency_off` используется на окончании серии и при аварии, но обрыв UART остаётся `UNKNOWN` до физического подтверждения; **не выполнять автоматическое переподключение или retry**.

После подтверждённого полного выключения оператором: оригинальный `R45FK_DENSE_CH1_20261031.events.jsonl`, `channel_1.csv` и `completed.json` сохраняются без перезаписи. До независимого аудита они означают лишь завершение примера.

## Только офлайн-проверка и построение SVG

```bash
python3 tools/r4_5_1n4933_dense_plot.py \
  reports/hardware/R45FK_DENSE_CH1_20261031 \
  --out reports/hardware/R45FK_DENSE_CH1_PLOT_20261031
```

Выход: `diode_iv.svg` (напряжение непосредственно на диоде vs расчетный ток), `diagnostics.json` (SHA-256, 31+30 точек, минимум/максимум, оценки несогласованности прямого/обратного по развертке проходов). `NO_LARGE_ANOMALIES_DETECTED` НЕ закрывает метрологическую аттестацию; нужны оригинальные журналы и независимая проверка SCPI, OFF, монотонности, гистерезиса и физической схемы.

После последнего подтверждённого прогона ВАХ как **пример** закрываем и возвращаемся к Roadmap: capabilities прибора и совместимый hardware-API для будущих источников питания. Новую лабораторную оркестрацию в PSU-библиотеку не добавлять.
