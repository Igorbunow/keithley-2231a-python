# R3.5.11 — отдельная OFF-only диагностика зависимости Aux от канала

## Статус

Это диагностический вариант **H01_AUX_REVISION**, не полная H01, не повтор H02/H03 и не разрешение на активные испытания. Основная библиотека уже допускает изменение firmware revision при стабильных manufacturer/model/serial, не игнорируя реальные ошибки связи, статуса или уставок.

## Гипотезы и ограничения

В архиве H01–H04 были значения `Main 1.04 / Aux 1.04` и `Main 1.04 / Aux 0.01`; версия `1.01` отдельно замечена пользователем в меню, но пока не зафиксирована в `*IDN?` evidence. Смена выбранного канала могла влиять на Aux, однако старые трассы не дают доказательства причинности. Меню и SCPI сообщают одну версию в момент наблюдения. Официальное руководство не описывает зависимость версии от выбранного канала.

Диагностика читает *IDN? при последовательности `CH1, CH1, CH2, CH2, CH3, CH3, CH1, CH3, CH2, CH1`. Повтор в рамках одного канала контролирует временную изменчивость, а возврат к CH1 проверяет обратимость. В будущем может потребоваться проверка в иных условиях, но этот эксперимент ограничен OFF-only.

## Политика безопасности

- Физически все три канала **OFF**, все клеммы свободны, нет DUT, нагрузки, перемычек, общей шины. Output Recall = OFF; доступен сетевой выключатель.
- Только Keithley USB–TTL, с идентификатором адаптера из общего `bench.local.toml`. KEL103/DMM/oscilloscope не открываются.
- После подтверждения соединения и отдельного подтверждения свободных клемм драйвер проверяет `CHAN:OUTP?` всех каналов. По ходу опыта проверяются `CHAN:OUTP?` выбранного канала, `OUTP:STAT:ALL?`, бит ON во всех трёх `ISUM` регистрах. После цикла вновь проверяются `CHAN:OUTP?` всех каналов.
- Разрешённые записи: `SYST:REM`, `INST:NSEL 1/2/3`, `SYST:LOC`. **Запрещены** любые `OUTP`, `CHAN:OUTP` записи, изменение уставок/лимитов, `*CLS`, `*RST`, `SYST:MODU?` (не проверен отдельно).
- Если ответ повреждён, режим Series/Parallel активен, выход ON, выбранный канал не совпал или истёк лимит — дальнейшие команды по недостоверной связи **не отправляются**. Нет reconnect/retry, нет автоматической попытки выключить выход при неизвестной связи. Требуется физическая проверка OFF.
- Финальное физическое подтверждение обязательно для PASS. Результат сохраняется отдельно как `H01_AUX_REVISION` и не меняет квалификационный статус других этапов.

## Запуск без оборудования

```bash
python3 tools/hw_qualify.py preflight H01 --aux-revision-diagnostic --config config/bench.local.toml
python3 tools/hw_qualify.py run H01 --aux-revision-diagnostic --config config/bench.local.toml --dry-run
```

**Не переходить сразу к `--execute`.** Сначала проверить патч, полный offline-набор, readback ALL OFF и отдельно подтвердить физическое состояние. После явного допуска оператора предназначенная команда:

```bash
python3 tools/hw_qualify.py run H01 --aux-revision-diagnostic --config config/bench.local.toml --execute
```

Исполнение требует локального терминала и двух разных текстовых подтверждений *до открытия порта*, а также финального подтверждения физического OFF. Обычный `run H01 --execute` остаётся прежним.

Для сохранённого нового журнала:

```bash
python3 tools/audit_hw_scpi.py reports/hardware/<timestamp>_H01_AUX_REVISION/events.jsonl
```

В `events.jsonl` сохраняются номер пробы, выбранный и проверенный канал, строка Main/Aux как есть, `firmware_revision_drift`, реальные проводные команды и результат; серийный номер в `*IDN?` редактируется перед записью. Нельзя считать CH3 определённой причиной до получения такого controlled evidence.
