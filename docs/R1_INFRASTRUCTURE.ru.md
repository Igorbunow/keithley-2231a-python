# R1 — Рефакторинг инфраструктуры аппаратных тестов

**Статус: реализация и программная регрессия пройдены; повторная проверка на железе не проводилась.**

## Границы модулей

- `src/keithley2231a/` — самостоятельная библиотека для Keithley, не зависит от тестовых приборов.
- `tests/hardware/bench_config.py` — единая проверяемая конфигурация подключений.
- `tests/hardware/equipment/` — минимальные независимые адаптеры KEL103, DMM7510, TDS3064B.
- `tests/hardware/equipment/factory.py` — единое открытие физических соединений.
- `tests/hardware/*_stage.py` — подтверждённые точки испытаний, проверки и обязательные ручные подтверждения.
- `tests/hardware/qualification.py` — диспетчер, аудит и журналы.

## Запуск

```bash
cp config/bench.example.toml config/bench.local.toml
# Проверить подключения по фактическому стенду
python3 tools/hw_qualify.py preflight H01 --config config/bench.local.toml
# Только после согласования схемы
python3 tools/hw_qualify.py run H01 --config config/bench.local.toml --execute
```

Все адреса и скорости интерфейсов, а также ожидаемые USB VID:PID задаются
в `bench.local.toml`. Нельзя указывать отдельные IP/порт для каждого теста.
KEL103 использует только явно выбранный транспорт, без автоматического
переключения при ошибках. Отпечаток файла SHA-256 включён в evidence.

**Принципиальная граница:** проверенные значения уставок, сопротивления нагрузки,
допуски и разрешённые команды — часть самого тестового сценария, а не свободно
редактируемая оператором конфигурация. Изменение этих значений требует review
и повторной квалификации; возможность обойти лимиты через TOML не добавляется.

## Что удалено

Удалены дублирующие драйверы из файлов H03/H05, старый файл
`tests/hardware/dmm7510.py` и четыре альтернативных метода изменения CR.
Теперь единый `_KEL103Core` выполняет проверку команд, логирование, обработку
обрывов и верификацию нагрузки для UART и UDP. Исключены старые CLI-флаги
подключения. Обратные обёртки и deprecated-методы не создавались.

## Результат

130 тестов обнаружено, из них 128 успешных и 2 пропущены из-за отсутствия
`pyserial` в изолированной среде. С реальным оборудованием команды не выполнялись.
Старые аппаратные отчёты H01–H12 сохранены, но их PASS относится к предыдущему
исходному коду. Минимальная повторная квалификация: H01 (только чтение), затем
H03 (KEL103), H05 (TDS3064), H08 (DMM7510); затронутые объединённые сценарии
H09/H10 повторять по результатам ревизии безопасности.

Черновой `BenchCoordinator` и относящиеся только к нему тесты удалены: общий
координатор появится позже, в отдельном проекте.
