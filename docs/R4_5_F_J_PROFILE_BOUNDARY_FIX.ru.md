# R4.5-F-J.1 — границы драйвера и исправление отказа TTY (software only)

## Причина дефекта

`test_cli_run_refused_without_tty` полагался на фактический `sys.stdin.isatty()`.
В интерактивном терминале проверка принимала реальный TTY, проходила этап
предварительной валидации и открывала заведомо несуществующий `/nonexistent`.
Это дефект детерминированности **теста**, а не подтверждённая ошибка SCPI.
Теперь тест явно моделирует отсутствие TTY и проверяет, что `SerialTransport`
не создаётся. `--run` остаётся аппаратным режимом и требует независимого допуска.

## Граница библиотеки

Перенесены без дублирующих совместимых алиасов:

- `src/keithley2231a/sweep.py` → `examples/iv_sweep.py`;
- `src/keithley2231a/coordination.py` → `examples/iv_coordination.py`;
- `src/keithley2231a/monitor.py` → `examples/acquisition.py`.

Вместе с ними из публичного `keithley2231a.__init__` удалены
`voltage_sweep`, `SweepPoint`, `TimedVoltageObserver`,
`coordinated_voltage_sweep`, `verify_coordinated_csv`, `Acquisition`,
`ChannelStats`, `RollingStats`. Их задачи — host scheduling, прикладной CSV,
наблюдатели других приборов, статистика — не способности Keithley 2231A.
Существующие H07/H11/O01 квалификационные этапы теперь импортируют
те же реализации из `examples/`, без второй SCPI-диспетчеризации.
Это намеренное несовместимое изменение предварительного API (0.2.1.dev0).

В `src` сохраняются аппаратные возможности SCPI, безопасные профили,
ограничение токов/напряжений, управление выходами и safety monitor состояния
**самого PSU**. Перенос `start_profile_monitor` не выполняется: этот монитор
реализует проверку профиля и аварийную реакцию драйвера, в отличие от
прикладного `Acquisition`.

## Следующие решения (в этот патч не входят)

- R5: machine-readable *capability metadata* конкретного прибора:
  каналы, пределы, шаги DAC/readback, accuracy conditions, поддержка
  аппаратных триггеров/таймеров, combined-mode и статус реальной проверки.
  Capability описывает операции и ограничения, но не предписывает ВАХ.
- Отдельная верхняя библиотека выбирает native fast path либо host-side
  fallback и полностью владеет многоприборной последовательностью.
- Отдельный MCU-проект может предоставить raw TCP → UART, RFC2217 или
  эксклюзивный firmware-backed HTTP API, не превращая `src` в gateway.
- Нет аппаратных подтверждений CH2/CH3 профильного ВАХ; тесты только симуляционные.

Старые исходные архивы и отчёты H07/H11/O01 не переписываются:
их аппаратные доказательства были собраны с предыдущим API.
Реальные процедуры требуют собственной повторной проверки после изменения
импортов; этот этап новых аппаратных команд не отправлял.
