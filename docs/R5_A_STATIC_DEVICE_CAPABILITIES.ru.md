# R5-A — статические аппаратные возможности Keithley 2231A-30-3

## Задача

Библиотека описывает **возможности конкретного прибора**, а не реализует
планировщик измерений. В другом проекте верхний слой сможет выбрать между
поддерживаемой аппаратной операцией и общей host-реализацией; создание общего
протокола для всех производителей здесь не требуется.

`Keithley2231A.capabilities()` и `keithley2231a.get_capabilities()` возвращают
один неизменяемый описатель без UART/TCP/SCPI и без необходимости открывать порт.
`to_dict()` выдаёт независимую JSON-совместимую копию `schema_version=1`.

```python
from keithley2231a import Keithley2231A
import json
caps = Keithley2231A.capabilities()  # no device I/O
print(caps.channel(3).rated_voltage_v)  # 5.0
trigger = caps.feature("hardware_triggered_setpoint")
print(trigger.instrument_native, trigger.driver_exposed)  # True False
print(json.dumps(caps.to_dict(), indent=2))
```

## Разделяем три независимые оси

1. **`instrument_native`** — оборудование/firmware имеет такую возможность;
   это не команда её выполнить и не разрешение включить выход.
2. **`driver_exposed`** — обычный защищённый API библиотеки предоставляет
   функцию. Отсутствие не означает, что SCPI-команда не существует.
3. **`evidence`** — исторический характер подтверждения: `bounded_hw`
   (только изученные режимы и firmware), `simulated_only`, `documented_only`,
   `absent`. Даже `bounded_hw` не является общей поверкой и не отменяет
   проверки профиля, топологии, состояния и соединений.

Метаданные статичны: они **не** проверяют идентификатор подключённого прибора,
фактическое firmware, калибровку, наличие внешних перемычек или безопасный OFF.
Нужно выполнять эти проверки отдельно в реальной сессии.

## Электрические параметры и ограничения

CH1/CH2: 0–30 В, 0–3 А; CH3: 0–5 В, 0–3 А. Сетка уставок: 0,01 В / 0,001 А.
Номинальная погрешность readback при 25±5 °C по спецификации прибора:
напряжение ±(0,06% показания + 20 мВ), ток ±(0,2% показания + 10 мА).
Это **не сертификат точности текущего прибора**. Номинальная разрешающая
способность считывания тока 1 мА и большое число десятичных знаков в ответе
SCPI — не гарантия точности в микромперном диапазоне.

Для R4.5-F-K зарегистрирована только диагностическая прямая ВАХ на CH1:
`docs/hardware_reports/R4_5_F_K_1N4933_61POINT_INDEPENDENT_REVIEW.ru.md`.
В многоканальных протоколах H09/H10 комбинированные режимы квалифицированы
лишь в ограниченных условиях. `parallel` не гарантирует подтверждённое
равномерное распределение тока; `series` не означает безусловно проверенный CC.

## Что НЕ добавлено

- SCPI и новые команды включения, триггеры, sweep-движок, внешний DMM;
- общего `Instrument`/`Bench` интерфейса для других производителей;
- MQTT, Modbus, веб-сервера, шлюза Ethernet, владения портами;
- автоматического подбора профиля, изменения установленного профиля,
  скрытого обхода interlock или восстановления после потери UART.

Верхний проект, решая как делать ВАХ, должен интерпретировать
`native_iv_sweep=False`, `atomic_voltage_current_sample=False`, а также
погрешности токового readback. Экспериментальную логику и алгоритм измерения
оставляем в `examples/` либо в будущем самостоятельном приложении.

## Дальнейший R5

После проверки этого минимального, безаппаратного контракта — типизированный
API выбора CH1/CH2/CH3 с делегированием имеющимся проверкам `device.py`, без
копирования SCPI, затем версия профилей и контракт соединения/владения.
Отдельный будущий шлюз MCU/UART/TCP не входит в данную библиотеку.
