# R5-D3 — независимая квалификация STEP на CH1/CH2/CH3

**Дата:** 31 октября 2026 года. **Решение:** HW REVIEWED PASS, *только в проверенной области*.
Проверены нативные `VOLT:STEP`, `VOLT:UP/DOWN` в CV и `CURR:STEP`,
`CURR:UP/DOWN` в CC на каждом из CH1, CH2, CH3. Одна проверка — один
канал и один режим. Объединённый автоматический силовой запуск не проводился.

## Протокол и ограничения

- CV: исходная уставка 3,30 В, ограничение 0,150 А, KEL103 CR 40 Ω,
  `VOLT:STEP 0.010`; команды UP/UP/DOWN/DOWN.
- CC: уставка напряжения 3,30 В (верхняя граница), исходная уставка
  тока 0,100 А, KEL103 CR 11 Ω, `CURR:STEP 0.005`; те же четыре команды.
- DMM7510 в FRONT DCV непосредственно параллельно нагрузке; измерения
  PSU / KEL103 / DMM выполнялись **последовательно**, не одновременно.
- В каждый момент только выбранный канал разрешён на ON; независимая
  топология без внешних перемычек. Заявленный потолок процедуры — 0,60 Вт.
- Для каждого опыта ровно 7344 записи JSONL, 1634 SCPI-запроса, пять
  измерительных точек, четыре нативные STEP-мутации, нулевая очередь ошибок,
  цифровой OFF всех каналов после отключения и подтверждение оператора,
  что нагрузка обесточена. Никаких ошибок KEL103/DMM и нарушений пределов
  офлайн-аудитор не обнаружил.

## Интерпретация результатов

1. В CV физическое напряжение изменялось при каждом STEP приблизительно
   на ±10 мВ, по внешнему DMM7510. Последний DOWN возвращал его близко
   к первому показанию. Расхождение CH1/CH2/CH3 по абсолютной уставке
   допускает влияние падения в проводах и некалиброванных условий.
2. В CC ток KEL103 изменялся приблизительно на ±5 мА, а внешнее
   напряжение изменялось приблизительно на ±55 мВ с нагрузкой CR 11 Ω.
   Это **не** проверка абсолютной точности измерения тока на уровне 0,1 мА:
   показания PSU отличаются от KEL/DMM и источники измерений не калиброваны
   в рамках опыта. Финальное остаточное отклонение CH2/CC по DMM ~3,396 мВ
   (~0,309 мА для номинальных 11 Ω) и не указывает на провал шаговой функции.
3. На CH1/CC наблюдался firmware `1.04-0.01`; на остальных запусках —
   `1.04-1.04`. Это уже известное нестабильное поле Aux из `*IDN?`.
   Из него не следует изменение рабочего режима/успеха STEP.
4. Все шесть файлов фиксируют `source_dirty: true`. Перед запуском
   оператор вывел `git status --short`, где перечислены неотслеживаемые
   исторические файлы в `docs/hardware_reports/`; строки `git diff --name-only`
   и `git diff --cached --name-only` были пусты. Версия commit — `1b121ff`,
   а хеши runner, stage, исходников и bench config совпали во всех шести
   журналах. Эти факты нужно сохранять вместе с отчётом; это не
   автоматическое подтверждение отсутствия любого скрытого изменения.

## Дополнительные OFF-only испытания

`VOLT:STEP 0.010` с UP/UP/DOWN/DOWN по CH1, CH2 и CH3 отдельно
проходили ранее 31.10.2026 при всех выходах OFF; три серии были
проверены независимо по 4449 событиям каждая. В этом пакете исходные
OFF-only JSONL **не приложены**, поэтому машинный агрегатор ниже проверяет
лишь шесть powered CV/CC случаев. Исторические подтверждения
`CURR:STEP` CH1/2/3 (9 цифровых OFF-only комбинаций) остаются без изменений:
`docs/reviews/R4_5_D_CURRENT_BATCH_HW_REVIEW_2026-10-30.md`.

## Что НЕ квалифицировано

- Работа во всём паспортном диапазоне 30 В/3 А (CH1/CH2) и 5 В/3 А (CH3),
  минимальные/максимальные шаги, тепловой режим, точность или быстродействие.
- Одновременные/атомарные измерения, синхронность каналов, transient waveform,
  переключение в Series/Parallel/Tracking и нагрузочные точки H09/H10.
- Общедоступный API для произвольных STEP при ON — остаётся существующий
  защищённый квалификационный контекст с операторскими gate.
- `VOLT/CURR:TRIG`, `*TRG`, `INST:COUP`, `APPLy` и `OUTP:ENAB`:
  не подвергались этим испытаниям и остаются недоступными через обычный API.
- Отказоустойчивость при потере связи не является аппаратно гарантированным OFF.

## Воспроизведение аудита (только офлайн)

Положите шесть исходных JSONL в отдельную папку и вызовите:

```bash
python3 tools/audit_r5_d3_step_matrix.py \
  '/папка/events(20261031-013513).jsonl' \
  '/папка/events(20261031-013504).jsonl' \
  '/папка/events(20261031-013457).jsonl' \
  '/папка/events(20261031-014706).jsonl' \
  '/папка/events(20261031-014655).jsonl' \
  '/папка/events(20261031-014648).jsonl'
```

Ожидаемый результат `SIX_ORIGINALS_REAUDITED_MATCH_BOUNDED_REVIEW`.
В отличие от простого `PASS` скрипт проверяет уникальность шести оригиналов,
SHA-256, версию исходников, конфигурацию и 30 аналоговых значений.
Техническое решение о допустимости конкретного будущего опыта всё равно
принимается независимо от статического capabilities.
