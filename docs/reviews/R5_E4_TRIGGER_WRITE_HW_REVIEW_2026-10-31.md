# R5-E4 — независимый обзор аппаратной записи регистров TRIG (2026-10-31)

**Заключение:** CH1/CH2/CH3 — `REVIEWABLE_PASS_OFF_ONLY_NOT_TRIGGER_ACTUATION`.

Испытания проведены на реальном Keithley 2231A-30-3 с подключением только
UART и пустыми выходными клеммами. Оригинальные JSONL независимо проверены
`tools/audit_r5_e4_trigger_write.py`. Реальных событий `*TRG`, проверки
`INST:COUP` или силовых измерений не было. Заключение ограничено чтением,
записью и обратным восстановлением триггерных регистров в режиме OFF.

| CH | Исходно, В / А | Проба, В / А | Восстановлено, В / А | События SYST:ERR? |
|---|---|---|---|---|
| 1 | 0 / 0 | 2.200 / 0.120 | 0 / 0 | Только 0, No error |
| 2 | 0 / 0 | 0.800 / 0.080 | 0 / 0 | Только 0, No error |
| 3 | 0 / 0 | 0.800 / 0.080 | 0 / 0 | Только 0, No error |

Все три оригинальных файла содержат 1058 SCPI query и 81 OFF-readback;
физический OFF в конце каждого опыта подтверждён оператором. Наблюдалась
прошивка `1.04-0.01` — уже известный переменный вариант Aux в IDN.
Активные независимые уставки CH1 3.30 В/0.150 А и CH2/CH3 1.00 В/0.100 А
не изменились во время манипуляций с TRIG-регистрами.

SHA-256, исходный source/config/runner/stage provenance и точное соответствие
каналов см. в `R5_E4_TRIGGER_WRITE_HW_EVIDENCE_INDEX_2026-10-31.json`.
Пользовательские имена файлов при загрузке не совпали с номерами каналов:
`032303` = CH3, `032309` = CH2, `032316` = CH1. Сопоставление
производилось по полю `channel` в оригинальном JSONL и его SHA-256.
`source_dirty: true` отмечено в файлах: последующее подтверждение состава
рабочего дерева не следует заменять предположением о чистом Git.

### Что **не доказано**

* Отправка `*TRG`, команда `TRIG`, эффект на активные уставки, внешний аналоговый выход.
* Какие каналы отвечает на bus trigger, грамматика и текущее состояние `INST:COUP`.
* Точность, синхронизация, гарантированное время переключения или безопасность при нагрузке.
* Любое состояние Series/Parallel/Tracking и полноценные диапазоны прибора.

Следующий этап — планировать эксперимент с учётом **всех** трёх потенциальных
получателей триггера. Никакой автоматический переход к силовому `*TRG` не допускается.
