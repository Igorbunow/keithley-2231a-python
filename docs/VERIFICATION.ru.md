# Матрица подтверждения функций на оборудовании

**Повторная квалификация текущего кода:** H01 пройден read-only. H02 прошёл OFF-only профиль с разными значениями, ограничение панели, soft-защиту библиотеки и gated-проверку отказа прибора (HW OBSERVED). H03 прошёл все шесть CV/CC точек на текущем runner: подтверждены показания нагрузки и дисплеев, выключение каждого канала и финальный OFF. Сохраняется оговорка статуса OPER CH3=`8`, при QUES=`1/2` и согласии readback/панели/нагрузки. H04 прошёл OFF-only этап на текущем runner: панельные лимиты различались по каналам, soft-cap и tamper-проверки прошли, итоговый OFF подтверждён. H05 прошёл низкомощную трёхканальную последовательность с захватом TDS, сверкой KEL103/PSU, чистой очередью ошибок и финальным OFF. Таймерная часть H06 прошла на стенде: CH1/CH2/CH3 отключились за 3,051/3,063/3,056 s и повторно включились при отключённом таймере; все 841 ответа очереди ошибок чистые, финальный OFF подтверждён. Первая попытка остановилась до включения из-за ошибок runner; исправления прошли offline 95/95. Output Recall прошёл четыре сетевых цикла: OFF `111→000`, ON `101→101`, `010→010`, `000→000`; Save Last оставался ON, все 970 ответов очереди ошибок чистые, Recall OFF восстановлен, финальный физический OFF подтверждён. H06 PASS в проверенном объёме; offline-тесты сами по себе не подтверждают работу прибора.

**Обозначения:** `HW VERIFIED` — подтверждено настоящим прибором с полным протоколом; `HW OBSERVED` — наблюдение на реальном приборе без полного протокола; `SIM TESTED` — проверено программным эмулятором; `HW UNVERIFIED` — работа на железе ещё не подтверждена; `PLANNED` — функция пока запланирована.

Оператор сообщает версию меню испытанного экземпляра: Main **1.04** / Aux **0.01**. Поле revision в сырых ответах `*IDN?` менялось между `1.04-1.04` и `1.04-0.01`; оно записывается, но не считается идентичностью устройства. Библиотека проверяет производителя/модель/серийный номер и поддерживает опциональную привязку к serial. Другие версии не блокируются кодом, но их поведение остаётся неквалифицированным до отдельных испытаний.

## Как перевести возможность в HW VERIFIED

Для каждой функции создать отчёт в `docs/hardware_reports/` по [шаблону](hardware_reports/TEMPLATE.md): дата, версия исходников/коммит, модель и прошивка, нагрузка, соединение, ожидаемые ответы, реальные ответы, проверка DMM/осциллографом, погрешности/оговорки. Серийные номера перед публикацией удалить или обезличить. Прежде чем считать результат пройденным, отдельно проверить ошибки связи/некорректные параметры, а не только штатную работу. Изменения версии библиотеки и прошивки требуют переоценки квалификации.

**Зелёные тесты GitHub Actions — только подтверждение логики на эмуляторе, не реального источника.** Библиотека не заменяет независимую аппаратную защиту.

### Исправление H01, ожидает повторной проверки — 2026-10-26

После H01 оператор увидел в меню прибора `170, Invalid command`. Последним
запросом был `OUTP:PARA?`. Синтаксис OUTPUT в руководстве — `PARallel`, но
