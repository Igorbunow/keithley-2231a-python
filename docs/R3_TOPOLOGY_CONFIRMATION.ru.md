# R3.1 — обязательное подтверждение физической топологии

**Статус:** программная квалификация; повторное аппаратное испытание ещё не выполнялось.

Для независимых каналов и Tracking оператор должен вручную убедиться,
что между CH1/CH2 **нет внешних Series/Parallel перемычек**.
Только после проверки и при выключенных выходах разрешается применять профиль:

```python
psu.apply_profile(profile, confirmed_wiring='independent')
```

В Series/Parallel остаётся обязательным соответствующий токен `series`/`parallel`
после установки **физических внешних соединений** при отключенных выходах.
Токен не является электрическим измерением: введение ложного подтверждения
не может быть распознано драйвером. Переход обратно в Independent или Tracking
**не снимает провода автоматически**. Наличие перемычек не определяется SCPI.

При отсутствии либо несоответствии токена вызов отвергается **до SCPI**,
не снимает и не заменяет уже установленный профиль. Старый неявный API удалён.
Все примеры и аппаратные сценарии обновлены; существующие ручные
подтверждения у H09/H10 перед снятием перемычек сохранены.

## Критерии проверки R3.1

1. При отсутствии/неверном токене Independent/Tracking: отказ без единой команды SCPI.
2. После Parallel → emergency_off(): без `independent` нельзя перенастроить
   прибор и исчезновение программного режима Parallel не считается снятием проводов.
3. При явно подтверждённой оператором независимой проводке профиль принимается,
   результат — все три выхода OFF.
4. Старые сценарии и эмуляторные тесты проходят.
5. Позднее на железе: адресная повторная проверка H09/H10 при
   отсоединённой нагрузке и отключенных выходах, **с отдельным
   операторским подтверждением снятия перемычек**. На этом этапе
   включение выходов не требуется.

**Ограничение:** это программный interlock на действия оператора,
не аппаратная OVP/OCP/межблокировка.
