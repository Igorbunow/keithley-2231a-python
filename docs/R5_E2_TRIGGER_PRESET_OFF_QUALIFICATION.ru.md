# R5-E2 — аппаратная квалификация чтения нативных триггерных регистров

Статус: **SOFTWARE TESTED / REAL HARDWARE NOT RUN / NO TRIGGER ACTION**.

Цель: на реально подключённом Keithley 2231A-30-3 независимо проверить ответы
`VOLT:TRIG?` и `CURR:TRIG?` на **каждом CH1/CH2/CH3**. Это не проверяет
переход по событию `*TRG`, coupling, временные характеристики, применение
уставок, абсолютную точность или синхронизацию. Выходы должны быть OFF.

## Существенная граница безопасности

Метод `Keithley2231A.read_trigger_presets(ch)` (R5-E1) требует действующего
независимого профиля с control-access. Поэтому R5-E2 сначала **изменяет только
выключенные активные профили**: CH1 3.30 В / 0.150 А; CH2/3 1.00 В / 0.100 А;
ограничения по напряжению 3.50/1.50/1.50 В. Это действия `VOLT`/`CURR`,
**не** `VOLT:TRIG`/`CURR:TRIG`. Применение профиля требует отдельного
операторского подтверждения. Нельзя утверждать, что *весь* runner read-only:
read-only являются **два триггерных запроса**, выполняемых после профиля.

Строгий wire allowlist блокирует `*TRG`, `TRIG`, `INST:COUP`, любые записи
`VOLT:TRIG`/`CURR:TRIG`, `OUTP 1`, `CHAN:OUTP 1`, `APPLy`, reset, recall и
непредусмотренные SCPI. После каждой проверенной команды polling очереди
`SYST:ERR?`, который сам по себе удаляет одну запись из очереди ошибок.
Устройства KEL103/DMM7510/TDS3064B для этапа **не нужны**, клеммы
всех каналов источника остаются пустыми.

## Перед аппаратным запуском

1. Применить и закоммитить R5-E2 после R5-E1 (`9dce59e`); выполнить полный
   software regression, убедиться в корректном SHA staging и `compileall`.
2. Физически проверить CH1/CH2/CH3 OFF, пустые клеммы, отсутствие проводов,
   DUT, перемычек Series/Parallel/Tracking, соединений с другими источниками.
3. Убедиться, что у прибора нет другого активного программного владельца,
   нет предварительно настроенного Recall/таймера и блокировок интерфейса;
   настройки OFF-профиля будут изменены.
4. Dry-run для каждого канала **без** `--execute` и без открытия USB:

```bash
python3 tools/r5_e2_trigger_read_qualify.py --config config/bench.local.toml --channel 1
python3 tools/r5_e2_trigger_read_qualify.py --config config/bench.local.toml --channel 2
python3 tools/r5_e2_trigger_read_qualify.py --config config/bench.local.toml --channel 3
```

## Операторские аппаратные испытания — только после отдельного согласования

Каждый запуск — **ровно один канал** и четыре независимых подтверждения:
BENCH, INITIAL, PROFILE (разрешение изменить OFF-профиль), QUERY (два
запроса), плюс FINAL после физической проверки выключения. Пример CH1:

```bash
python3 tools/r5_e2_trigger_read_qualify.py \
  --config config/bench.local.toml --channel 1 --execute
```

При завершении runner напечатает путь к **оригинальному** `events.jsonl`.
Запустить независимый (полностью offline) аудитор, не изменяя JSONL:

```bash
python3 tools/audit_r5_e2_trigger_read.py \
  "/путь/из/вывода/runner/events.jsonl"
```

Ожидаемый технический результат аудитора:
`REVIEWABLE_PASS_NOT_TRIGGER_ACTUATION` с SHA-256 и двумя числовыми
регистрами в паспортных пределах CH1/CH2 0–30 В, CH3 0–5 В,
все CH 0–3 А. Сам статус аудитора **не** означает полной аппаратной
квалификации до анализа реального SCPI журнала.

Нельзя автоматически запускать CH2 вслед за CH1 или CH3 вслед за CH2.
Между случаями — физическая проверка OFF и отдельное разрешение оператора.
Любой таймаут, неожиданная уставка, неизвестная прошивка, плохой ответ,
отказ проверки OFF или неопределённость UART — остановить испытания,
физически убедиться в OFF, не повторять автоматически запросы.

## Что будет подтверждено и что останется открытым

Если три реальные оригинальные проверки пройдут независимо, добавим
узкое `HardwareEvidence` к `trigger_preset_readback` для CH1/CH2/CH3 с
реальными SHA оригинальных JSONL и observed firmware. Не объявляем
поддержку `*TRG` или `INST:COUP?` аппаратно доказанной по этим результатам.

Последующий этап R5-E3: отдельно исследовать безопасную запись отложенных
регистров и coupling (спецификация `INST:COUP?` неоднозначна), затем —
управляемый low-power trigger на нагрузке с независимым DMM, если будет
подтверждена реальная грамматика. Каждый режим на всех поддерживаемых
каналах; без искусственных CH1-only ограничений.

Документация референса: Keithley 2231A-30-3 Reference Manual, 077100401,
разделы 5-4, 5-12, 5-25 и 5-27:
https://download.tek.com/manual/077100401_Referencemanual.pdf
