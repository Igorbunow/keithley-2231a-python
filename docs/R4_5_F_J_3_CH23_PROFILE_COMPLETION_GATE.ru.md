# R4.5-F-J.3 — программные шлюзы завершения примера ВАХ и кандидат CH2/CH3

Область: **только example**, не библиотека и не верхнеуровневый измерительный комплекс. Этот этап **не разрешает** аппаратный запуск и не повышает статусы аппаратной квалификации CH2/CH3. Существующие результаты CH1 не распространяются на другие каналы.

## Изменения

`examples/diode_iv.py`: до начала работы с каждым каналом, после применения аппаратного профиля и после `voltage_sweep()` читаются все три состояния `CHAN:OUTP?` через публичный `output_states()`. Наличие хотя бы одного ON или невозможность достоверно получить ответы прекращает пример **без положительного результата**. Защитные механизмы прибора и реализация `emergency_off()` не меняются. После цифрового OFF оператор отдельно проверяет физический OFF. При потере связи нельзя считать выход выключенным на основании последней успешной команды; запрещён автоматический повтор/переподключение.

После успеха **всех** выбранных каналов создаётся `completed.json`, включающий список каналов, источник тока, признак принудительного использования неточного PSU readback, операторские и цифровые подтверждения OFF, SHA256 отдельных CSV и SHA256 нормализованного описания профиля. Отсутствие `completed.json` означает **незавершённый пример**, даже если некоторые CSV имеются. Эта сводка подтверждает только исполнение example, **не независимый SCPI-аудит и не калибровку**.

`examples/diode_iv_ch23_qualification_profile.json`: кандидат для отдельных будущих аппаратных проверок CH2, затем CH3 при **выключенных** других каналах; 1N4933, R=99,86 Ом (измерено ранее), номинальная мощность балласта не менее 0,25 Вт, 0,80–0,90 В, токовый лимит 20 мА, CH2 три точки (возврат), CH3 две. Текущий DMM7510 может быть включён последовательно после CH1-эксперимента: до применения кандидата он должен быть **физически отсоединён от тестовой цепи или отдельно перекоммутирован в безопасный режим при OFF**; никаких предположений о входе AMPS делать нельзя. Профиль использует `force=true`, источник `PSU_READBACK_DIAGNOSTIC`, точность не подтверждена; DMM не нужен в этом диагностическом варианте.

## Только программные действия (до отдельного согласования аппаратных тестов)

```bash
PYTHONPATH=src python3 examples/diode_iv.py --profile examples/diode_iv_ch23_qualification_profile.json
PYTHONPATH=src:tests:tests/hardware:. python3 -m unittest discover -s tests -q
python3 -m compileall -q src tests tools experiments examples
git diff --cached --check
```

Аппаратный `--run` **запрещён** до отдельного согласования с оператором и проверки кабелей, диода, резистора, полярности, отсутствия Series/Parallel перемычек и внешних источников. На каждом этапе обязательно: все каналы OFF и физический OFF, подключение к **одному выбранному каналу**, защитный профиль на всех каналах, строго одно включение нужного канала, CV и реальные показания, OFF до любых изменений схемы, отсутствие подтверждения результата при ошибке SCPI/режима/связи.

Из примера не делаются заявления о точности тока, аппаратной задержке STEP, временной синхронизации, физической схеме лишь на основании SCPI или полной независимой аппаратной квалификации.

После независимой проверки логов будущих CH2/CH3 переход к roadmap: R5 capability metadata, R6 release preparation. Источник питания предоставляет аппаратные возможности, алгоритмы измерения принадлежат верхнему слою; идея будущего MCU UART-TCP/Web-шлюза не является частью этого патча.
