# R3.5.29 / O01 — последовательный координатор Keithley + DMM7510 (только offline)

**Статус: SIM TESTED, HW NOT_RUN.** Это первый программный инкремент O01,
а не разрешение аппаратного прогона. Изменение не добавляет CLI `O01 --execute`,
не открывает порты и не меняет последовательность SCPI H01–H12.

## Что реализовано

- `keithley2231a.coordination.TimedVoltageObserver`: принимает `Reading`
  после чтения PSU, затем вызывает **один** `meter.measure()` и записывает
  хостовые времена начала/окончания запроса DMM. Не делает retry.
- Контроль: DMM уже `live/configured`, число и диапазон ответа, явный режим
  `CV`/`CC`, рассогласование напряжения (по умолчанию не более 30 мВ),
  начало DMM-запроса в пределах 2 с от завершения PSU-чтения и полный
  интервал не более 5 с. Пределы задаются вызывающей стороной до I/O.
- `coordinated_voltage_sweep(...)` использует существующий защищённый
  `voltage_sweep(...)`. На ошибке DMM/наблюдателя срабатывает его
  `finally: device.emergency_off()`, без попыток повторного чтения DMM.
  На успешном завершении PSU также выключается. Это программная команда OFF;
  при потере связи её доставка физически не гарантируется — ручной OFF обязателен.
- CSV содержит отдельные `timestamp_utc`/`monotonic_s` PSU и семь
  дополнительных числовых полей DMM: `dmm_voltage_v`,
  `dmm_query_start_monotonic_s`, `dmm_query_end_monotonic_s`,
  `source_dmm_gap_s`, `source_dmm_window_s`, `dmm_query_duration_s`,
  `psu_dmm_delta_v`. `verify_coordinated_csv` сверяет все поля с
  полученными `SweepPoint` уже **после выключения**.

**Метрологический смысл:** `Reading.monotonic_s` соответствует времени
завершения последовательных SCPI-чтений PSU. Времена DMM обрамляют
выполнение `meter.measure()` на **том же хосте**. Нельзя считать их временем
преобразования АЦП приборов, аппаратной синхронизацией, общей временной
базой между приборными часами или строго ограниченной ошибкой
одновременности. Отдельно калибровать задержки и оценивать неопределённость
планируется после подтверждения аппаратной процедуры O01.

## Граница безопасности

Сейчас это **API, не hardware stage**. До будущего реального запуска необходимы:
отдельный O01 preflight, операторские проверки конфигурации и физических
проводов, независимо подтверждённые Keithley CH1/CH2/CH3 OFF и
KEL103 INPUT OFF (если нагрузка задействована), правильные клеммы DMM7510,
`SCPI`/`FRONT`/DCV и режим/диапазон. Никакой прямой запуск нового API с
подключённым оборудованием без такого stage/допуска не квалифицирован.

`voltage_sweep` сам выполняет программную последовательность включения
(после применения защищённого профиля) и глобальный OFF в `finally`.
В остальных каналах заранее должен быть OFF, как требует исходная библиотека.
Этот инкремент не меняет аппаратные подтверждения H10/H11/H12.

Добавлена отдельная [карточка O01 stage](O01_STAGE_PREFLIGHT.ru.md),
строгий SCPI scope и пилотный runner с тремя CV-точками без нагрузки.

`run O01 --execute` **явно блокируется до открытия портов**.
Автоматическое включение не разрешается результатом offline-регрессии.
