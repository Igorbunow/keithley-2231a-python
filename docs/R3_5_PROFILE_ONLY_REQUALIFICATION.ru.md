# R3.5.2 — ограниченная переквалификация Independent (OFF-only)

## Назначение

После R3.1–R3.4 повторно подтвердить штатное применение защищённого профиля
Independent на реальном 2231A **без включения выходов**. Не повторять полную
историческую H02: в ней есть ручная проверка Max Volt Set и заведомо
отвергаемые диагностические SCPI-команды. Эти дополнительные проверки не входят
в R3.5.2.

Одна функция `h02()` и один объект `guarded_profile()` обслуживают оба варианта:
полный H02 (без `--profile-only`) и ограниченный R3.5.2. Нет второго драйвера,
другой схемы отправки SCPI или самостоятельной реализации управления уставками.

## Что разрешено и что исключено

- Начальное условие: CH1/CH2/CH3 OFF, KEL103 INPUT OFF и **физически** отключён;
  без перемычек Series/Parallel/Tracking, DUT и внешней общей шины. Проверить
  `Output Recall=Off` и доступность сетевого выключателя.
- Используется `config/bench.local.toml` для интерфейса, скорости и USB VID:PID;
  автоматическая проверка USB и общий `CONFIRM BENCH H02-PROFILE-ONLY SHA256=...`.
- Отдельное физическое подтверждение `CONFIRM H02 PROFILE_ONLY ...` сообщает,
  что внешняя схема проверена человеком; программно обнаружить перемычки нельзя.
- Уставки и caps ограниченной *фиксированной квалификационной точки* берутся из
  существующего `H02_CHANNELS` в `tests/hardware/profile_stage.py`, не из
  сетевых настроек: CH1 1.00 V / 0.100 A, V-cap 2.00 V / I-cap 0.300 A;
  CH2 1.50 V / 0.200 A, V-cap 3.00 V / I-cap 0.400 A;
  CH3 2.00 V / 0.300 A, V-cap 4.00 V / I-cap 0.500 A.
- Runner через общий драйвер читает исходное состояние и режим, отвергает
  недопустимый ON до применения профиля, выполняет `apply_profile()` с явным
  `confirmed_wiring='independent'`, проверяет `verify_profile()`, уставки,
  timers и выходы через readback, проверяет запрет недопустимых API-уставок до
  SCPI, завершает `emergency_off()` с подтверждением OFF, возвращает CH1 и LOC.
- **Нет** запросов `OUTP 1`/`CHAN:OUTP 1`, ручных изменений панели, `VOLT 2.01`
  / `3.01` / `4.01`, `debug_bypass_profile`, намеренных ненулевых SCPI ошибок,
  автоматических повторов и переподключений. Не переподключать DUT или нагрузку
  в ходе исполнения.
- При ошибке/неопределённой связи — останов и явный UNKNOWN, физическая
  проверка OFF. Отправка `OUTP 0` сама по себе не является подтверждением OFF.
- Уставки после успешного теста **остаются изменёнными**; выходы OFF. Это
  важное отличие от полностью немутирующего H01.

## Команды

Предварительный просмотр без соединения с приборами:

```bash
python3 tools/hw_qualify.py preflight H02 --profile-only \
  --config config/bench.local.toml
```

Аппаратный запуск **только после отдельного согласования схемы и разрешения**:

```bash
python3 tools/hw_qualify.py run H02 --profile-only \
  --config config/bench.local.toml --execute
```

В отличие от полного H02, limited-отчёт записывается под именем
`*_H02_PROFILE_ONLY_qualification.md`, evidence содержит
`qualification_variant=profile_only`. Это **не** полный PASS H02 и не
продвигает квалификационную матрицу H02 автоматически. Для официального
завершения R3 требуется разбор отчёта и физическое подтверждение OFF.

## Замечание об источниках рабочих точек

Сценарные уставки H02 пока централизованы *в профиле H02*, а параметры
подключений — в `bench.local.toml`. Отдельный аудит H03–H12 выявил
дублирование строк уставок между пре-флайтами, runner и evidence. Массовый
перенос сценариев в TOML нельзя делать незаметно вместе с аппаратной
переквалификацией: требуется отдельный валидатор диапазонов, синхронное
обновление SCPI-allowlist, токенов подтверждения и регрессионных тестов.
