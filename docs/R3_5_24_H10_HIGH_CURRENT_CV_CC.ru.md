# R3.5.24 — H10: high-current CV + CC (offline candidate)

## Причина

Подтверждённые аппаратные прогоны R3.5.23:

- `run H10 --high-current --execute`: только CC 4.000 A, CR 0.50 Ω, около 2.0 V / 8.0 W, PASS.
- `run H10 --execute`: **не** full powered, а OFF-диагностика, штатный `PARTIAL` без `OUTP 1`.
- `run H10 --powered --execute`: отдельные низковольтные CV 3 V / CR30 и CC 0.3 A / CR5.

Никакого неявного полного силового прогона H10 нет: сценарии изолированы намеренно.

## Новая последовательность `--high-current` (требует нового approval)

1. Независимые PSU CH1/2/3 OFF; KEL103 INPUT OFF; установлен операторский Parallel с двумя перемычками подходящего сечения, KEL103 и DMM7510, CH3 полностью открыт. Для KEL силовой кабель 10 AWG, проверять также **сечение, обжим и контакты обеих перемычек**.
2. Подтверждение высокотокового gate, профиль Parallel 3.00 V / 4.000 A (software caps 4.00 V / 4.50 A). Значение `VOLT:LIM:STAT?` для пары может возвращаться OFF; 4 V не является аппаратной OVP.
3. **CV3A**: KEL103 CR 1.00 Ω, ожидаем примерно 3 V / 3 A / 9 W. Четыре измерения PSU/KEL/DMM, проверки тока, напряжения, мощности <=10 W, CR и V×I. Отдельный операторский gate CV.
4. Принудительный Keithley OFF с readback, KEL INPUT OFF с readback. Пока оба OFF не подтверждены, никакого изменения CR и следующего `OUTP 1`.
5. **CC4A**: KEL103 CR 0.50 Ω, ожидаем около 2 V / 4 A / 8 W. Четыре измерения PSU/KEL/DMM и отдельный gate CC.
6. Выключение обоих устройств с readback, физическое отсоединение KEL103/DMM и **обеих** перемычек оператором, восстановление Independent с readback; аварийный finalizer R3.5.23 остаётся неизменным.

Оба этапа в одном выполнении `--high-current` требуют одного нового разрешения для этой конкретной последовательности. Отдельные 120-секундные подтверждения CV и CC сохраняются.

## Ограничения доказательств

- Это **offline-only изменение**, не hardware-qualified. Старый аппаратный CC4A PASS остаётся самостоятельным результатом R3.5.23.
- Предел KEL 10 W — программная проверка по очередной измерительной выборке, **не мгновенный аппаратный ограничитель мощности**. Уставка 3 V и нагрузка CR 1 Ω проектируют около 9 W с запасом; возникновение ошибки прекращает последовательность.
- Показания DMM7510, Keithley и KEL103 считываются последовательно, а не синхронно.
- Тест подтверждает **общий** ток Parallel, но не баланс токов в индивидуальных каналах CH1 и CH2.
- Финальный `PARTIAL` OFF-диагностики не означает FAIL; для силовых тестов всегда нужен явный `--powered` либо `--high-current`.
- После FAIL/ABORTED автоматический повтор силового испытания запрещён до анализа evidence и оператора.

## Проверки

```sh
python3 tools/hw_qualify.py preflight H10 --high-current --config config/bench.local.toml
python3 tools/hw_qualify.py run H10 --high-current --dry-run --config config/bench.local.toml
PYTHONPATH=src:tests:tests/hardware python3 -m unittest discover -s tests -v
python3 -m compileall -q src tests tools
```

Перед реальным `--execute` нужна отдельная проверка обновлённого патча, его staged SHA и полное физическое подтверждение схемы. Не выполнять силовую команду автоматически после применения патча.
