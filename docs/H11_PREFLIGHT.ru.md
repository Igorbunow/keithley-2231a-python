# H11 — Низкоэнергетическая I–V развертка

Используется только CH1, независимый режим и электронная нагрузка KEL103 в режиме
CR 40 Ω. Настоящий диод не подключается. Runner вызывает публичный
`voltage_sweep()`; все SCPI-команды Keithley идут через общий debug dispatcher и
ограниченный `StageAdapter`.

## Подготовка

- Keithley 2231A-30-3 подключён к `/dev/ttyUSB3`, UART 9600 8N1; KEL103 подключена
  по USB к `/dev/ttyACM0`, 115200 8N1.
- Все выходы PSU выключены, вход KEL103 выключен, Output Recall выключен.
- Нагрузка отсоединена от клемм; перемычки, общая шина, осциллограф и DMM сняты.
- Выход сетевого выключателя Keithley доступен.

Runner установит уникальный профиль каналов:

| Канал | Уставка V/I | Предел V/I |
|---|---:|---:|
| CH1 | 0.50 V / 0.040 A | 2.00 V / 0.100 A |
| CH2 | 1.50 V / 0.200 A | 3.00 V / 0.200 A |
| CH3 | 2.00 V / 0.300 A | 4.00 V / 0.300 A |

Перед включением появится отдельная пауза. Только при PSU OFF и KEL INPUT OFF
подключить CH1+ к KEL103 INPUT+, CH1− к INPUT− короткими проводами. CH2 и CH3
оставить свободными. Runner настроит KEL103 CR 40 Ω.

## Один проход

Библиотечный sweep задаст 0.50, 1.00, 1.50 и 2.00 V с токовым пределом 0.040 A,
пауза установления 0.5 s и остановка при CV→CC. При CR 40 Ω ожидается ограничение
около 1.60 V / 0.040 A; мощность — около 0.064 W и не должна превысить 0.10 W.
Runner сверит монотонность I–V, показания KEL103, CC-точку, CSV и очередь ошибок.

Команда только готовит карточку, не обращается к приборам:

```sh
PYTHONPATH=src:tests/hardware python3 tools/hw_qualify.py preflight H11 --config config/bench.local.toml
```

## Допуски

Разрешить один проход только после проверки подготовки и подключения:

```text
CONFIRM H11 INDEPENDENT ALL_OFF LOAD=KEL103 DISCONNECTED USB=/dev/ttyACM0 BAUD=115200 RECALL=OFF CH1=V0.50_I0.040_VCAP2.00_ICAP0.100 CH2=V1.50_I0.200_VCAP3.00_ICAP0.200 CH3=V2.00_I0.300_VCAP4.00_ICAP0.300 CR=40OHM SWEEP=0.50,1.00,1.50,2.00 I_LIMIT=0.040A STOP=CC
```

После автоматического отключения PSU/KEL входа физически отсоединить KEL103 от CH1.
Затем подтвердить пустые клеммы и OFF:

```text
CONFIRM H11 CH1=OFF CH2=OFF CH3=OFF LOAD=OFF DISCONNECTED
```

## Результат H11 — 2026-10-27

**PASS (HW OBSERVED) для указанного ограниченного сценария.** Получены четыре
точки, первые три в CV и последняя в CC; публичный sweep остановился на CC и
записал проверенный CSV:

| Уставка V | Keithley, V / A / W | KEL103, V / A / W | Режим |
|---:|---:|---:|---|
| 0.50 V | 0.501004 / 0.011282 / 0.005652 | 0.4978 / 0.0122 / 0.0060 | CV |
| 1.00 V | 1.000530 / 0.023816 / 0.023829 | 0.9976 / 0.0247 / 0.0246 | CV |
| 1.50 V | 1.499790 / 0.036257 / 0.054378 | 1.4964 / 0.0373 / 0.0558 | CV |
| 2.00 V | 1.631500 / 0.039763 / 0.064873 | 1.6282 / 0.0404 / 0.0657 | CC |

506 ответов Keithley `SYST:ERR?` были `0, "No error"`. После прогона все три
канала и KEL INPUT прочитаны OFF; оператор подтвердил физическое отключение
KEL103. Это проверка одного CR-ряда и согласованности показаний, не точности
калибровки и не ВАХ полупроводника.

Два первоначальных запуска были прерваны до включения выхода: первый из-за
попытки читать через запрещённый прямой debug transport; второй из-за ошибочных
имён полей при формировании profile evidence. Оба дефекта исправлены; итоговая
offline-регрессия прошла **121/121** до успешного аппаратного повтора.
