# Диагностика подключений испытательного стенда

Сначала выполнить **read-only inventory**, затем конкретный preflight H01–H12.
Это **разные процедуры**: `preflight` по умолчанию печатает план (DRY RUN)
и **никогда не проверяет физическую доступность оборудования**.

```bash
python3 tools/hw_qualify.py inventory --config config/bench.local.toml --execute
```

Опрос продолжается для **всех четырёх** устройств, даже если одно из них
недоступно, занято другим процессом, имеет неверную идентификацию или не
отвечает на команду. В конце выводятся результаты для Keithley 2231A,
KEL103, DMM7510 и TDS3064B с причиной ошибок. Код возврата `0` означает
четыре успешные проверки, `2` — хотя бы одна неудачная, **после проверки всех**.

Собираются только идентификация и минимальная информация о режиме подключения:

- 2231A: проверка USB VID:PID и `*IDN?` через общий UART-транспорт;
- KEL103: `*IDN?` и `:INP?` через общий адаптер;
- DMM7510: `*IDN?`, `*LANG?` через общий адаптер; необходим режим SCPI;
- TDS3064B: `*IDN?` через общий e*Scope-клиент.

**Никакие выходы не переключаются, уставки не меняются, перезагрузки, очистки
очередей ошибок или автоматического переподключения нет.** Для e*Scope запрос
`*IDN?` передаётся HTTP POST с SCPI-запросом, но не содержит команды изменения
состояния. Состояние выходов и безопасное подключение остаются ответственностью
оператора: inventory не заменяет H01 и **не присваивает HW VERIFIED**.

Журнал создаётся в исключённом из Git каталоге
`reports/local/inventory/<timestamp>_<id>/inventory.jsonl`. При необходимости
можно указать явный путь `--evidence PATH` (существующий журнал не перезаписывается).
Параметры всех подключений берутся только из `config/bench.local.toml`.

Команда без `--execute` остаётся чистым dry-run:

```bash
python3 tools/hw_qualify.py inventory --config config/bench.local.toml
```

После успешного inventory выполнить H01 отдельно, сначала `preflight`,
затем `run H01 --execute` с подтверждениями оператора. **PASS inventory ≠ PASS H01**.
