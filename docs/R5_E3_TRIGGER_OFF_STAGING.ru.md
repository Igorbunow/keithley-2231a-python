# R5-E3 — программная подготовка OFF-only записи триггерных регистров

**SOFTWARE/PTY ONLY. НА РЕАЛЬНОМ ПРИБОРЕ НЕ ПРОВОДИЛОСЬ.**

`stage_trigger_presets_off(ch, voltage_v, current_a, confirmed_off_only=True)`
для CH1/CH2/CH3 требует Independent control profile, подтверждённого OFF
всех выходов, соблюдения профиля и сетки 10 мВ / 1 мА. Это пределы
текущего безопасного сценария, не ограничение паспортной функциональности.
Последовательность НЕ атомарная: `VOLT:TRIG N.NNN`, `VOLT:TRIG?`,
`CURR:TRIG N.NNN`, `CURR:TRIG?`, с проверкой ошибок после каждой команды.
Активные `VOLT`/`CURR` и другие каналы не должны измениться.

До первой записи драйвер фиксирует латентную неподтверждённую триггерную
уставку. Любой `OUTP 1` / `CHAN:OUTP 1` запрещён на этой сессии, даже после
повторного apply_profile. Новая программная сессия НЕ очищает физические
триггерные регистры. При неопределённой связи не выполнять слепой retry.
`*TRG`, `TRIG`, `INST:COUP`, `APPLy` остаются заблокированы; скрипты аппаратного
включения эта стадия не предоставляет.

Следующий этап только по отдельному разрешению: один канал за раз,
пустые клеммы, OFF-only trigger-write readback со строгим wire allowlist,
внешним подтверждением и оригинальными JSONL с независимым аудитом.
Силовой тест `*TRG`, coupling, latency/jitter и реальная синхронизация —
отдельные этапы, не подтверждённые R5-E2 или R5-E3.
