# R4.5-F-J — завершающий профильный пример ВАХ (software stage)

**Приоритет проекта — библиотека Keithley 2231A-30-3, не лабораторный оркестратор.**
Пример `examples/diode_iv.py` заменён профильным вариантом, использующим
**только существующие публичные** `Profile`, `ChannelProfile`, `apply_profile()`,
`voltage_sweep()` и `emergency_off()`. Новых методов/SCPI-команд в `src/` нет.

## Профиль и допуск метода

Пример `examples/diode_iv_profile.json` показывает один профиль с последовательными
каналами CH1, CH2, CH3. Каждый канал содержит **ровно один** способ задания
напряжений: `points_v` (в явном порядке, повторы/обратный ход допустимы) **или**
`range_v` с `start_v`, `stop_v`, `step_v` (восходящий диапазон, точно включающий
конечную точку). Все значения кратны 10 мВ. От 1 до 100 точек на канал.

В профиле явно указываются измеренное сопротивление и мощность балласта,
ограничение тока, допустимая абсолютная ошибка тока (мА), `current_source`
(`auto`, `psu`, `external`) и `force` (булево). Предварительный план проверяет
все каналы **до открытия портов**, запрещает дубликаты/неизвестные ключи,
напряжения выше 5 В (для примера; CH3 имеет паспортный предел 5 В), лимит
тока выше 50 мА, питание закороченного диода выше заданного токового лимита
`Vmax/R`, перегрузку резистора `Vmax²/R` и нереализуемый шаг.

При выборе внутреннего считывания тока расчётный **номинальный верхний предел**
по спецификации 2231A-30-3 — `10 мА + 0,002 × I`. Эта величина условна
(условия паспорта 25±5 °C, калибровка и неопределённость не проверены).
Выбор:

- `auto`: если номинальный паспортный предел readback **не хуже** требуемого
  `max_current_error_ma`, применяется телеметрия PSU, иначе нужен внешний
  амперметр.
- `psu`: если заявленная точность выше паспортной, профиль отклоняется;
  `force=true` допускает **только диагностическое**, заведомо менее точное
  использование PSU readback.
- `external`: требуется внешний наблюдатель тока для **каждой** точки.
  Пример не реализует его драйвер, не переключает диапазоны, не меняет
  проводку и не синхронизирует приборы. Верхний проект может внедрить
  callback `external_observers[channel](reading)` в `run_profile()`.
  Отсутствующий callback блокирует выполнение *до SCPI*.

`force` **не** отменяет электрические пределы, проверку профиля, ограничения
проводки, подтверждения оператора и аварийный OFF. Для внешнего источника
`force=true` запрещён. Все экспортируемые токи имеют признак
`accuracy_qualified=false`. Никаких поправок вроде +1 мА к данным PSU нет.

## Запуск

```bash
PYTHONPATH=src python3 examples/diode_iv.py \
  --profile examples/diode_iv_profile.json
```

Это **исключительно офлайн**: профили CH1/CH2/CH3 будут разобраны,
выведены режимы тока и условный предел readback, без открытия портов.

**`--run` не выполнять до отдельного согласования аппаратной части каждого
канала, проверки соединений и утверждения плана.** Для последующей ручной
аппаратной квалификации предусмотрен `--run --port <UART> --output-dir <new>`.
Нужен интерактивный терминал; перед каждым каналом и его включением отдельно
проверяются схема, полярность, сопротивление и физически выключенные выходы,
после sweep требуется подтверждение физического OFF. Профиль применяется
заново для каждого канала, потому что примерный `voltage_sweep()` из `examples/iv_sweep.py` глобально выключает
все три выхода и снимает программное разрешение по окончании каждой серии.
**Одновременно каналы никогда не включаются**. При обрыве связи безопасный
аппаратный OFF только программными средствами не гарантирован.

В CLI можно выполнить профили с `force=true` или достаточным для PSU
`max_current_error_ma`. Если нужен внешний DMM, **CLI намеренно отклоняет**
`--run`: многоприборная оркестрация должна остаться в отдельном верхнем проекте.
При заданном внешнем callback вызывается только `voltage_sweep(observer=...)`;
это не является аппаратной квалификацией ни одного DMM-режима.

Выходной каталог создаётся новым, существующий не перезаписывается. CSV
`channel_N.csv` записывается **после** успешного выполнения и OFF; каждый
ряд содержит уставку/измеренное U PSU, отдельный readback I PSU,
выбранный ток, грубую оценку `U_diode=U_PSU-I·R`, источник и явный флаг
отсутствия метрологической квалификации. Для CC или неполной серии пример
отказывает вместо частичного «PASS». Это **host-timed** серия, не SMU,
не синхронный измеритель, не средство поверки.

## Остаточные аппаратные этапы (не закрыты этим патчем)

1. Отдельно на CH2 и CH3 подтвердить реальную последовательность команд,
   лимиты напряжений/тока, readback, CV/CC, OFF и сохранение операторских
   подтверждений; **в настоящее время только виртуальный UART**.
2. Внешние измерения тока по каждому каналу требуют отдельного согласования
   схемы и оператора, не переносятся с ранее проверенного CH1 автоматически.
3. По успешном завершении аппаратных проверок профиля закрыть пример ВАХ
   и вернуться к основному `ROADMAP.md`: SCPI coverage, API/capabilities,
   package/release hardening. Верхний экспериментальный framework не входит
   в scope этой библиотеки.
