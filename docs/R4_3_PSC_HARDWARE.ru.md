# R4.3-B — аппаратная проверка `*PSC?` (только чтение)

**Статус: HW REVIEWED PASS, ограниченный одноразовый OFF-only опрос**
`*PSC?` на реальном Keithley 2026-10-29. Независимый аудит исходных
логов: [R4_3_PSC_review_2026-10-29.md](hardware_reports/R4_3_PSC_review_2026-10-29.md).
Приведённая ниже процедура остаётся инструкцией для нового, отдельно
согласованного запуска; повторение для подтверждения уже полученного PASS
не требуется.

Источник: Keithley 2231A-30-3, *Reference Manual* 077100401, §5,
стр. 5-6. Документирована форма `*PSC?` как чтение флага управления
поведением ESER/SRER при включении питания. Документация не обещает
конкретного значения на всех версиях firmware. API возвращает 0 либо 1,
без предположений о значении по умолчанию.

`*PSC` **не отправляется**, не проверяется эффект перезапуска и не
предпринимается сброс питания. *Это не измерение выходов вольтметром*.

## Требования до подключения

- Один Keithley, без нагрузки, DUT, межканальных перемычек и других активных
  контроллеров. CH1/CH2/CH3 физически OFF, Independent, Recall OFF.
- `config/bench.local.toml` соответствует фактическому адаптеру и USB VID:PID.
- Запрет на `OUTP 0` даже в качестве cleanup: это наблюдательный тест.
  При неизвестном состоянии связи дальнейшая связь прекращается;
  физический OFF подтверждает оператор независимо.
- Разрешённые записи: **только** `SYST:REM`, `INST:NSEL 1/2/3`, `SYST:LOC`.
  `*PSC`, `*CLS`, `*ESR?`, `STAT:*:EVEN?`, `*RST`, триггеры и уставки запрещены.
  `SYST:ERR?` после валидных запросов потребляет очередь ошибок.

## Запуск

Сначала без связи с приборами:

```bash
python3 tools/r4_3_psc_qualify.py --config config/bench.local.toml
```

Затем, **только после физической проверки и согласия оператора**:

```bash
python3 tools/r4_3_psc_qualify.py --config config/bench.local.toml --execute
```

Стадия проверяет статусы каждого выхода в начале и в конце, topology,
`*IDN?` до/после, `*ESE?`/`*SRE?` до/после единственного `*PSC?`,
исходный выбранный канал, нулевые ошибки и конечное операторское подтверждение.
Все SCPI с ответами и sha256 runner/stage записываются в отдельный
`reports/hardware/*_R43_PSC_READ_ONLY/events.jsonl` (не перезаписывается).
`PASS` от программы — лишь кандидат; `HW REVIEWED PASS` допустим
**только после независимого анализа** JSONL и терминального журнала.

Если `*PSC?` даёт не 0/1, код SCPI не 0, либо связь прерывается —
**ABORT**, повторять на том же соединении нельзя. Прибор в неизвестном
состоянии проверить физически; никаких автоматических OFF-команд.

**Ограничения**: нет проверки фактического сброса ESER/SRER после power-cycle,
поведения SRQ, или аппаратно установленного режима Output Recall.
