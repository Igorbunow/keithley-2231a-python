# R4.5-F-C — контракт измерительного тракта DUT (offline; HW NOT_AUTHORIZED)

**Статус:** предварительная программная проверка схемы; не квалифицированный аппаратный runner, не подтверждение правильности проводки, не разрешение на подключение DUT. Основа — принятый R4.5-F-A CR40 и успешный автономный экспорт R4.5-F-B. Новый тип DUT и его паспортные границы оператор ещё не указал.

## Почему нельзя просто подключить DUT рядом с KEL103

В конфигурации R4.5-F-A KEL103 измеряет **свой ток**, а PSU — суммарный ток всех внешних ветвей. Если подключить DUT параллельно электронной нагрузке, показание KEL103 не будет током DUT. DMM7510 FRONT DCV измеряет напряжение параллельно; измерения одновременно не происходят. Ни имеющаяся программа ВАХ, ни одношаговый powered guard не выдавали разрешение на такой DUT.

Для *будущего предварительного скрининга* предусмотрен только следующий электрический вариант:

```text
Keithley CH1 (+) ── [известный внешний балласт R] ── (+) пассивный DUT (−) ── Keithley CH1 (−)
                                                  │                     │
                                                  └── DMM7510 FRONT DCV ┘

KEL103: физически полностью отсоединён; CH2/CH3: без подключений;
прочие параллельные нагрузки, внешние источники, перемычки и DUT с накопленной энергией: ЗАПРЕЩЕНЫ.
```

DMM показывает именно напряжение **на DUT** при корректно выбранных точках подключения. `Keithley MEAS:CURR?` показывает общий ток CH1, включая возможный входной ток вольтметра, токи утечки и паразитные ветви. В схеме лишь одна намеренная силовая ветвь. Это **предварительный скрининг**, НЕ независимое измерение тока DUT, НЕ метрологически квалифицированная универсальная ВАХ. Абсолютная погрешность, ток входа DMM и падение напряжения на балласте требуют отдельной оценки. Для полноценных независимых U/I понадобятся два совместимых измерительных маршрута (например, отдельный последовательный датчик тока вместе с независимым измерением напряжения DUT).

## Программный проверяющий контракт

`tools/r4_5_dut_topology_review.py` — стандартная библиотека Python, только чтение JSON, **никакого** импорта instrument drivers, serial/TCP/USB/VISA, открытия оборудования, отправки SCPI, создания evidence или файлов. Конкретный проект заполняется на основе `docs/examples/R45FC_DUT_plan.example.json`. Сам пример **намеренно отклоняется**, поскольку в нём нет настоящего идентификатора, установленных номиналов и верифицированной полярности.

Обязательны: явный тип пассивного двухполюсного неэнергогенерирующего DUT; подтверждённые паспортные пределы прямого напряжения/тока/мощности; полярность; физически отдельный известный балласт; отсутствие КEL103, других нагрузок и внешнего питания. Разрешён только контракт на пять уставок `start → UP → UP → DOWN → DOWN`, где `max = start+2*step`.

Зашитые верхние проектные границы **для допуска к дальнейшему проектированию**, не для включения:

| Параметр | Граница |
|---|---:|
| Верхняя уставка CH1 | 1,0 В |
| Ограничение тока CH1 | 20 мА |
| Максимальная рассчитанная мощность DUT | 20 мВт |
| Длительность powered-сеанса в плане | 30 с |
| Шаг | 10–100 мВ |
| Минимальное документированное сопротивление балласта | 50 Ω |

Проверяющий требует `R_ballast × I_limit ≥ V_max` (ограничение тока при условном пассивном КЗ), паспортную мощность балласта не менее `2 × V_max² / R_ballast`, запас паспортных DUT-пределов и условие `V_max × I_limit ≤ P_DUT_max`. Проверки основаны на **значениях, заявленных составителем плана**, и не верифицируют реальный резистор, паспорт DUT, токовую характеристику, динамику или защиту при обратном/внешнем напряжении. Эти неравенства не заменяют реальную независимую защиту, осмотр и одобрение схемы.

`--plan` создаёт только stdout JSON со статусом `DESIGN_CHECK_PASS_POWERED_NOT_AUTHORIZED`, SHA плана, узлами измерений, численными пределами и ограничениями. При любой ошибке — `DESIGN_REJECTED` и код 2. Даже успешный `DESIGN_CHECK_PASS` всегда содержит `hardware_authorized=false` и `independent_current_measurement=false`.

```bash
python3 tools/r4_5_dut_topology_review.py --plan docs/examples/R45FC_DUT_plan.example.json
# ОЖИДАЕМО: DESIGN_REJECTED; HW NOT_AUTHORIZED

# После отдельного выбора конкретного пассивного DUT и известного балласта:
python3 tools/r4_5_dut_topology_review.py --plan /path/to/private-dut-plan.json
# Возможный статус: DESIGN_CHECK_PASS_POWERED_NOT_AUTHORIZED
```

Не размещайте конфиденциальный план, паспортные номера, фотографии подключений или сырые аппаратные логи в публичном Git без отдельной проверки. Проверка не открывает новые powered-полномочия и не меняет production-драйвер или старые пути CR40.

## Что нужно для следующего реального испытания

Выбрать **конкретный** DUT с известными безопасными характеристиками, типом, полярностью и предельной мощностью, подтвердить наличие и номинал внешнего балласта, определить токовый измерительный маршрут. Затем отдельно разработать операторски подтверждаемый stage с независимым OFF, проверкой реальных U/I, отказом при первой аномалии и offline UART/fault тестами. Только после этой работы возможен `--execute` и последующий независимый hardware review. Для неизвестного/активного/накопительного/полярно-неоднозначного DUT текущий скрининг непригоден.
