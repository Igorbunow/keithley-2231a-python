[Русский](RECIPES.ru.md) | [English](RECIPES.md)

## Три сценария профилирования

| Режим | Как создать | Разрешённые действия |
| --- | --- | --- |
| Ограниченный с управлением | `Profile(..., channels=(ChannelProfile(...), ...))` | Менять уставки в пределах профиля, измерять, включать выходы |
| Полный паспортный диапазон | `Profile.unrestricted()` | Устанавливать напряжение/ток в пределах **паспортных** значений без дополнительных лимитов приложения |
| «Только питание» | `Profile(..., access='power_only', power_sequence=(PowerStep(...), ...))` | Только включение и выключение зафиксированных каналов, без изменения уставок/таймера/порядка |

**Профиль сначала отключает все выходы, задаёт ограничения и уставки, затем разрешает управление.** Никаких автоматических включений после `apply_profile()` нет. У установленного профиля нельзя менять режим объединения CH1/CH2 без отключения/переприменения.

При `power_only` порядок задаётся кортежем `PowerStep(channel, delay_s)`: задержка *перед* включением очередного канала. Выключение — в обратной последовательности с соответствующими обратными промежутками. Если последовательность задана, отдельная команда `output(1, True)` отклоняется. Если не задана, `power_on` применяет порядок CH1→CH2→CH3 (без задержек), `power_off` — CH3→CH2→CH1, а отдельные каналы можно включать через API.

В JSON разрешены `"access": "power_only"` и массив `"power_sequence": [{"channel": 1, "delay_s": 0.0}, {"channel": 2, "delay_s": 0.5}]`. См. [`examples/power_only.json`](../examples/power_only.json).

**При использовании Series или Parallel обязательно физическое внешнее соединение силовых клемм CH1/CH2!** Программа не может объединить выходы внутри прибора. `confirmed_wiring` — подтверждение пользователя, а не автоматическая проверка проводников.

## Мониторинг

```python
from keithley2231a import Acquisition

log = Acquisition(psu, interval_s=2.0, csv_path='runs/power.csv')
log.run(duration_s=120)
log.export_summary('runs/power_summary.json')
print(log.stats[1].as_dict())
log.reset_statistics(1, reset_energy=False)
```

Фиксируются измерения с временными метками, состояние канала, текущие уставки, min/max/mean/σ, заряд А·ч и энергия Вт·ч. Измерения выполняются последовательно, поэтому мощность V×I является оценкой. А·ч/Вт·ч интегрируются по **фактическим** интервалам, большие разрывы исключаются. Это не измерение ёмкости разряжаемого аккумулятора — источник не является электронной нагрузкой.

## ВАХ резистора или диода

```python
from keithley2231a import voltage_sweep

# Только после подготовки ограниченного профиля и маломощного стенда!
# points = voltage_sweep(psu, 1, [0.0, 0.5, 1.0, 1.5],
#                        current_limit_a=0.020, settle_s=0.5,
#                        csv_path='runs/diode.csv')
# u_diode_est = [x.measured_v - x.measured_a * 220 for x in points]
```

Для диода предусмотреть последовательно резистор, рассчитанный по максимальному напряжению и рассеиваемой мощности. `u_diode_est` грубо учитывает падение на R=220 Ом, но не погрешность сопротивления и падение на проводах. Лучше использовать DMM на выводах диода и `observer=lambda sample: {'diode_voltage_v': dmm.read_voltage()}`; API внешнего мультиметра обеспечивает конкретный адаптер. По окончании развертки библиотека пытается глобально отключить **все каналы**.

## Ethernet-мост в перспективе

`TcpTransport('psu-lab.local', 5025)` и `TcpTransport('192.168.1.73', 5025)` уже имеются. Это прозрачная передача команд UART по сети с **единственным управляющим клиентом**, а не сетевой SCPI-сервер, встроенный в Keithley. Микроконтроллеру понадобятся обработка обрыва, запрет конкурирующих клиентов, защита сети, тайм-ауты и, для ответственных стендов, независимое аппаратное аварийное отключение.
