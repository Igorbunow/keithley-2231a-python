# R3.5 — Единое подтверждение подключений стенда

## Единственный источник конфигурации

`config/bench.local.toml` — единственное место, где задаются пути UART, сетевые
адреса/порты, скорости обмена, тайм-ауты, модели и USB VID:PID приборов стенда.
Программа не предлагает вводить или менять эти значения в аппаратном тесте.
Для `run --execute` запрещён стандартный `bench.example.toml`: нужен явный
`--config` с локальной конфигурацией.
Все соединения создаются через `tests/hardware/equipment/factory.py` и активный
проверенный `BenchConfig`.

Перед **каждым** `hw_qualify.py run Hxx --execute` общая процедура
`tests/hardware/connection_gate.py` показывает параметры именно тех приборов,
которые использует этап, включая вложенные адаптеры KEL103, DMM7510 и TDS3064B.
Для UART автоматически сравнивает фактический путь устройства и USB VID:PID из
инвентаря ОС с `bench.local.toml` **до открытия соединения**. Ошибка — STOP.
Для TCP/HTTP печатает адрес/порт, а фактическая идентичность прибора проверяется
штатным оборудованием/runner при установлении связи. Адрес сам по себе не
подтверждает идентичность прибора.

Оператор сверяет показанный конфиг с физической схемой и вводит **один общий**
токен `CONFIRM BENCH Hxx SHA256=<12 первых знаков хеша>` (с уникальным суффиксом
для Recall/Powered/High-Current). Его нельзя использовать после изменения файла
конфигурации: изменится SHA-256. Неподтверждение останавливает этап до открытия
соединений. В evidence сохраняются хеш и список инструментов, показанный
оператору, без их серийных номеров.

**Важно:** этот общий gate подтверждает только заявленную конфигурацию соединений,
а не исправность, аппаратный OFF, перемычки Series/Parallel или разрешение
подавать напряжение. Поэтому отдельное подтверждение топологии, нагрузки,
ограничений и финального OFF в каждом аппаратном этапе **остаётся**. Без этого
включение выходов недопустимо.

`inventory --execute` остаётся отдельной диагностикой: читает идентификацию
и вход KEL103, но не требует подтверждения перед read-only опросом.
Проверка программных тестов не запускает никакие аппаратные стадии.

### Пример процедуры (только preflight, без оборудования)

```bash
python3 tools/hw_qualify.py preflight H01 --config config/bench.local.toml
```

Никаких «своих» скоростей, адресов или путей в аппаратных этапах быть не должно.
При обнаружении в конкретном runner нового дублирования параметров подключения
необходимо устранять его через `BenchConfig`, а не создавать второй файл.
Параметры *испытательных рабочих точек* (U/I/CR) и утверждение новых профилей
являются отдельной задачей аудита: их изменение требует пересмотра аппаратной
процедуры, а не молчаливого переноса опасных уставок.
