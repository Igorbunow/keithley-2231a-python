# R3.5.7 — отдельный CLI для CH1 Independent CV/CC

**Статус:** программный патч для предварительного review. Первое аппаратное
включение CH1 допускается только после успешных локальных offline-тестов,
физической проверки стенда и явных интерактивных подтверждений оператора.

## Область проверки

- Конфигурация: **только** `config/bench.local.toml`, раздел
  `[qualification.h03_single_cvcc]`; параметры соединений — из `[devices.*]`.
- Keithley CH1 в Independent: CV 4,00 В / 0,300 А / KEL103 CR40 Ω,
  CC 4,00 В / 0,250 А / KEL103 CR12 Ω; предел профиля 1,20 Вт.
- CH2/CH3 всегда OFF, их клеммы свободны. Никаких перемычек, общей шины,
  осциллографа или DUT. Нет автоматического переключения устройств/портов.
- Изменение Aux 1.04 ↔ 0.01 регистрируется в evidence, без подавления
  проверок идентичности, ошибок, выходов и лимитов.

## Подтверждения и последовательность

1. Только интерактивный терминал. Проверка reviewed PASS H01/H02,
   USB VID:PID источника и KEL103 **до открытия портов**.
2. Раздельно подтверждаются полная TOML-конфигурация и физическая схема:
   все каналы OFF, KEL INPUT OFF, CH2/CH3 отсоединены, Output Recall OFF,
   сетевой выключатель доступен; без перемычек, без DUT.
3. Загрузка открывается только с USB serial, источник — только по
   настроенному USB–TTL порту. Входная очередь SCPI и исходный OFF проверяются
   до программирования профиля. При неопределённой связи нет reconnect.
4. В каждом режиме CH1 остаётся OFF при изменении уставок и KEL CR.
   Затем отдельное подтверждение подключения/полярности CH1+, CH1−,
   включение KEL INPUT и отдельное разрешение **одного** CH1 ON.
5. Читаются регулирование CV/CC, измерения Keithley/KEL103, мощность,
   состояние CH2/CH3. При любом расхождении останов и контролируемый OFF
   только на канале связи, остающемся достоверным.
6. CH1 OFF до KEL INPUT OFF; подтверждение физического OFF. Пункт CC
   начинается только после успешного выключения CV. Финальное подтверждение
   OFF после двух пунктов. Если оно не получено, итог не может быть PASS.

Нельзя заменять этот запуск обычным `run H03 --execute`: у него иной,
трёхканальный маршрут. Второй флаг `--allow-single-cvcc-on` требуется даже
при `--single-channel-cvcc --execute`; тем самым старые команды не приобретают
новые полномочия после обновления ПО.

## Контрольный порядок для оператора

До аппаратного запуска проверьте повторно положение проводов, полярность,
выключенные выходы и вход KEL103, наличие физического выключателя питания,
отсутствие DUT/общей шины. При любой неожиданной индикации, нагреве,
запахе, нестандартном ответе или потере связи остановитесь и проверьте
OFF **физически**. Никаких автоматических повторов и переподключений.

Аудит завершённого запуска (чисто offline):

```bash
python3 tools/audit_hw_scpi.py reports/hardware/<timestamp>_H03_SINGLE_CVCC/events.jsonl
```

Аудитор проверяет порядок команд, запрет глобального ON, оба независимых
ON/OFF цикла, требуемые подтверждения и реальные ответы `SYST:ERR?`.
`PASS` аудитора не является доказательством метрологической точности;
после него отдельно исследуются напряжения, токи, status bits и физический OFF.

**Аппаратный результат должен быть проверен до нового испытания.**
