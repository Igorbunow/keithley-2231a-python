## Evidence review

Both CH3 powered points completed with live panel/load confirmations and met the H03
electrical comparison tolerances. CV measured 3.99576 V / 0.0998173 A / 0.398929 W on
Keithley and 4.0003 V / 0.0999 A / 0.3996 W on KEL103; CC measured 2.98031 V /
0.249532 A / 0.743684 W and 2.9840 V / 0.2487 A / 0.7421 W, respectively. All 190
Keithley `SYST:ERR?` replies were `0, "No error"`.

For both modes, `STAT:OPER:INST:ISUM3:COND?` was `8`, while
`STAT:QUES:INST:ISUM3:COND?` was `1` in CV and `2` in CC. The manual's status model
assigns CV/CC to bits 0/1 of both channel summary registers and output ON to operation
bit 3 ([Reference Manual, section 5 status model](https://download.tek.com/manual/077100401_Referencemanual.pdf)).
The physical mode behavior was observed, but the operation-register discrepancy leaves
status qualification unresolved; overall outcome remains PARTIAL. Review found a library
defect: `read_channel()` decoded mode only from operation status, although the manual also
defines CV/CC in questionable status. The driver now reads both registers, exposes both
masks in `Reading`, uses a single mode bit when the other register reports no mode, and
retains UNKNOWN on conflict. Offline regression passed 60/60; powered replay remains needed.
The raw event log contains the commands, actual responses, readings and operator gates.
Final channel and KEL103 input states were read OFF and physically confirmed OFF.
