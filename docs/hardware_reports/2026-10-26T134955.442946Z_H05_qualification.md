## Разбор причины и проверка исправления

Итог первого запуска — **ABORTED до подачи команды ON**, не PASS.
Оператор подтвердил CH1/CH2/CH3 OFF и KEL103 INPUT OFF.
H05 runner пропустил `SYST:REM` перед первым запросом статуса.
[Официальное руководство, §5-2](https://download.tek.com/manual/077100401_Referencemanual.pdf)
требует перейти в Remote перед работой с командами прибора.
Библиотека `apply_profile()` уже выполняла это требование; дефект находился
в предварительной проверке нового runner, выполнявшейся раньше профиля.

Диагностика без команд включения сохранена отдельно:
`reports/hardware/2026-10-26T135244.262033Z_H05_remote_diagnostic/events.jsonl`.
Прибор: Main 1.04 / Aux 0.01 (`*IDN?`: `1.04-0.01`), /dev/ttyUSB3, 9600 8N1.

| Команда | Фактический ответ |
| --- | --- |
| `SYST:ERR?` перед Remote | `-200, "Execution error"` — запись после предыдущего отказа |
| `SYST:REM` | Команда без ответа; следующая проверка ошибок успешна |
| `SYST:ERR?` | `0, "No error"` |
| `STAT:OPER:INST:ISUM1:COND?` | `0` |
| `STAT:OPER:INST:ISUM2:COND?` | `0` |
| `STAT:OPER:INST:ISUM3:COND?` | `0` |
| `SYST:ERR?` после чтений | `0, "No error"` |
| `SYST:LOC` | Команда без ответа, возврат локального управления |

Очередь ошибок не очищалась через `*CLS`: запись -200 была прочитана и сохранена.
Исправление: вход в Remote до чтения OFF-статусов. Адресная offline-регрессия
падает до исправления и проходит после него; полный набор: 77 тестов PASS
(`PYTHONPATH=src:tests:tests/hardware python3 -m unittest discover -s tests -v`).
Реальное чтение статусов после Remote успешно, но powered-последовательность
и её осциллограммы ещё не проверены. Уровень SEQ-01 остаётся HW UNVERIFIED.

## Текущий структурный ремонт и повторная квалификация

По требованию оператора исправление расширено до общего пути библиотеки.
Новый `output_states()` и диагностический API используют один диспетчер с обычными
методами. `debug=False` и обход профиля выключены по умолчанию. Специальный
`debug_bypass_profile` относится только к диагностическим записям; обычный API
сохраняет soft-проверки. Проверка H04P без обхода отклоняет 4.51 V до отправки,
затем явно включает обход для проверки ожидаемого аппаратного отказа 120.

H01–H05 переведены на общий StageAdapter и общие проверки. Скопированные
последовательности драйвера и отдельные пути raw-SCPI удалены. Фактическая UART
трасса статуса теперь включается библиотекой; runner не оборачивает `_serial`.
Общий offline-набор: 86 тестов PASS. Новые аппаратные результаты не заявляются.

Текущие H01/H02/H03/H04/H04P/H05 отмечены NOT_RUN для повторной квалификации
нового кода; исторический ABORTED этого отчёта не изменяется.
