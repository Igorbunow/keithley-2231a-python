`NOT_RUN`. Старое наблюдение UART/remote/IDN остаётся `HW OBSERVED`.

изменения этого этапа ещё не закоммичены. Python 3.13.5, pyserial 3.5, Linux.
Подготовка начата 25 октября и завершена 26 октября по Москве; дата матрицы
сохранена по исходному плану. Будущие журналы используют фактические UTC timestamps.

## Находки и исправления

| Приоритет | Доказанная проблема / риск | Действие до питания |
| --- | --- | --- |
| **Critical** | `power_only` пропускал изменение V/I внутри cap; допуски позволяли изменение на один шаг | Запоминаются разрешённые V/I, проверяются с допуском меньше половины шага. `control` обновляет ожидание после подтверждённого `set_channel` |
| **High** | OFF подтверждался только общим `OUTP:STAT:ALL?`, чей смысл при смешанном состоянии не определён достаточно чётко | После OFF читаются ON-биты каждого канала; регрессия моделирует оставшийся ON при общем ответе 0 |
| **High** | Внешнее включение канала при ожидаемом OFF не проверялось | Проверка поканальных ON-битов при `verify_profile`; аварийный отказ и попытка OFF |
| **High** | После timeout транспорт мог принять поздний ответ за следующий; UART молча удалял stale input | Отказ фиксируется до закрытия транспорта; повторные write/query запрещены. Stale UART input вызывает STOP; short write/oversize также ошибка. Нет автоматического reconnect |
| **High** | Ошибки `status()`/прочих прямых запросов могли оставить объект armed | Ошибки I/O разоружают объект; `status()` переводит в trip |
| **High** | Строка `output(1, 'OFF')` включала выход из-за truthiness | Требуется настоящий bool; номер канала — настоящий int. IDN проверяется по полям, не подстроке |
| **High / unresolved** | Совмещённые setpoint/readback могли ошибочно трактоваться как отдельные; global ON затрагивает CH3 | Включение Series/Parallel временно запрещено; setpoint-поля совмещённого `Reading` — `None`. Нет выдуманного преобразования 60 V/6 A в обычные команды. Требуется отдельное исследование H09/H10 |
| **Medium** | Профиль наследовал старые таймеры | При OFF таймер каждого канала отключается с readback до конфигурации V/I |
| **Medium / unresolved** | RWLOCK блокирует аварийные кнопки панели; чтение состояния блокировки не документировано | H01 не использует RWLOCK. Дальнейшие профили сначала `lock_front_panel=False`; физический сетевой выключатель доступен. Проверка внешней разблокировки не заявляется |
| **Medium / unresolved** | Tracking API запрещает изменение задания; remote-старт таймера не доказан | H08/H06 закрыты до отдельных безопасных сценариев и допуска. Нулевые уставки, связанные таймеры и комбинированные состояния требуют реальных наблюдений |

Слово «защита» не означает независимого электрического отключения. Raw transport,
другой процесс и панель способны вмешаться между опросами. Потеря USB не доказывает
OFF; после исключения нужна ручная проверка. POSIX UART использует exclusive-open,
но это не аппаратная блокировка стороннего контроллера.

## Сверка SCPI

Источник: [Keithley Reference Manual 077100401, September 2014](https://download.tek.com/manual/077100401_Referencemanual.pdf).
Проверены посылаемые команды и запросы; данные руководства не считаются результатом
исполнения прошивкой 1.04-1.04.

| Команды библиотеки | Раздел / страницы руководства | Вывод для квалификации |
| --- | --- | --- |
| `SYST:REM`, `SYST:LOC`, `SYST:RWLOCK`, `SYST:BEEP`, `SYST:ERR?`, `SYST:VERS?` | 5-17…5-18; remote prerequisite 5-2 | Синтаксис соответствует; RWLOCK не равен обычному panel key-lock. ERR? имеет побочный эффект извлечения записи; VERS — версия SCPI, не firmware |
| `*IDN?`, `*STB?` | 5-3…5-4 | IDN имеет четыре поля; serial скрывается, firmware читается заново. Не посылаются reset/clear/trigger |
| `INST:NSEL`, `INST:NSEL?` | 5-11 | Числовой выбор канала. H01 сохраняет выбор и не использует запись NSEL |
| `VOLT`, `CURR`, их `?` | 5-24…5-27 | Это команды/чтение уставок, не измерения. Ноль описан в диапазонах, приём конкретной прошивкой проверяется позже при OFF |
| `VOLT:LIM`, `VOLT:LIM:STAT`, их `?` | 3-5, 5-27…5-28 | Максимум задаваемого напряжения; не независимая OVP по измеренному выходу. Погрешность аналогового readback не применена к цифровому setpoint |
| `OUTP`, `OUTP:STAT:ALL?`, `CHAN:OUTP`, `CHAN:OUTP?` | 5-14, 5-24 | Global и выбранный канал различаются; агрегированный bool не доказывает индивидуальный OFF |
| `OUTP:ENABLE` | 3-5, 5-14…5-15 | Это отдельная маска допуска каналов через меню, не команда ON. Библиотека её не меняет; H01 не опрашивает неоднозначно документированный query |
| `OUTP:SER`, `OUTP:PARA`, `OUTP:TRAC`, их `?` | 3-6…3-8, 5-15…5-16 | Внешние провода обязательны для первых двух. Синтаксис PARA совпадает с примером; таблица сокращений непоследовательна. При неподдерживаемом запросе H01 остановится |
| `OUTP:TIM:STAT`, `OUTP:TIM:DEL`, их `?` | 3-6, 5-15 | Диапазон 0.1…99999.9 s. Описание запуска кнопкой не доказывает запуск через удалённый ON |
| `MEAS:VOLT?`, `MEAS:CURR?` | 5-13 | Последовательные измерения; W вычисляется как V×I, не одновременная метрология |
| `STAT:OPER:INST:ISUMx:COND?`, `STAT:OPER:COND?`, `STAT:QUES:COND?` | 5-19…5-24, status model 5-29…5-30 | По модели статуса CV=bit0, CC=bit1, ON=bit3. Нужна сверка с панелью в H01/H03. Event-register queries, очищающие регистры, не используются |

В руководстве есть опечатки: описание Series в SCPI упоминает parallel, тогда как
раздел 3 описывает сумму напряжений. Не использовать эту опечатку как определение
режима. Текст Fig.9/Fig.10 найден; **визуальная проверка клемм по самим рисункам
остаётся обязательной до H09/H10**, ни одна такая схема сейчас не разрешена.

`monitor` использует Welford и трапеции по монотонным временным меткам, пропуская
большие интервалы и OFF-пары. Это покрыто исходными offline-тестами, но не доказывает
точность PSU. `sweep` делает попытку global OFF в `finally`; ошибка OFF может скрыть
исходное исключение, поэтому фактическая доставка и ручной OFF проверяются отдельно.
`bench` выполняет операции последовательно; второго физического PSU/DMM нет в
подтверждённом составе стенда. O01/O02 остаются NOT_RUN, готовность оборудования — неизвестна.

## Offline-доказательства и изменённые файлы

Исходный `python3 -m unittest discover -s tests -v` дал **2 ошибки импорта**, потому
что пакет не установлен в системный Python. Запуск из source tree:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
# baseline: Ran 31 tests — OK
# after fixes: Ran 46 tests — OK (15 additional focused tests, parameterized cases)
python3 tools/hw_qualify.py list
python3 tools/hw_qualify.py preflight H01
python3 tools/hw_qualify.py run H01 --dry-run
# DRY RUN: порт не открыт, SCPI не отправлены.
git diff --check
```

До исправлений новые регрессии воспроизвели пропуск точных уставок/ON/OFF,
truthiness, неправильной identity и повторное использование транспорта. Результаты
H01 success/ON/wrong-model/error/timeout проверены только через fake transport.
Стандартный unittest-discovery включает offline-регрессии, но не исполняет
`tests/hardware/qualification.py`; в нём нет test-функций и запуска при импорте.

Изменения: `device.py`, `transport.py`, `tests/test_driver.py`; новый
`tests/offline/` (один regression-файл), `tests/hardware/qualification.py`,
`tools/hw_qualify.py`; `.gitignore`, обе `VERIFICATION*`, обе `HARDWARE_TESTS*`,
этот аудит и точная исходная матрица. Публичные сигнатуры сохранены. Намеренные
ужесточения: строгие bool/int/IDN, отказ транспорта после сбоя и временный запрет
включения Series/Parallel.

## H01: конкретный допуск

1. **ВСЕ выходы Keithley CH1/CH2/CH3 OFF**, проверить панель и отсутствие напряжения.
2. Вход электронной нагрузки **OFF**, её провода отсоединены от всех выходов PSU.
   Никакой режим CR/CC/CV и численное задание для H01 не нужны.
3. Нет DUT и внешних перемычек. Ничего не переставлять под напряжением.
4. На панели проверить `Output Recall = Off`; сетевой выключатель доступен.
5. Проверить, что `/dev/ttyUSB1` — нужный USB–TTL адаптер; 9600, 8N1. Закрыть другие
   терминалы. При запуске указать модель и VID:PID адаптера без serial.
6. Разрешаемая команда после отдельного подтверждения оператора:

```bash
python3 tools/hw_qualify.py run H01 --port /dev/ttyUSB1 --execute
```

Точное подтверждение: `CONFIRM H01 INDEPENDENT ALL_OFF LOAD=DISCONNECTED`.
Допуск включает только `SYST:REM`/`SYST:LOC` для режима управления и запросы из
`preflight H01`; `SYST:ERR?` извлекает одну запись ошибки. Уставки/caps неизвестны
и не меняются. Нет OUTP 1/0, изменения проводки, таймеров и блокировки панели.
Сначала/в конце читаются ON-биты всех каналов, дважды IDN; V/I — лишь выбранного
канала. Максимальная длительность одного прохода — 120 s, без автоматических
повторов. При I/O-сбое больше SCPI не отправляются, закрывается порт и требуется
ручная проверка выходов. При исправной связи LOC восстанавливается; OFF в H01
не посылается, поскольку это был бы выход за пассивный допуск.

Ожидаемое питание нагрузки — отсутствует; фактические электрические величины
ещё не измерены. При ошибочно включённом приборе паспортные пределы достигают
30 V/3 A на CH1/2, 5 V/3 A на CH3, 195 W суммарно — поэтому нагрузка отсоединена.
Независимый DMM не заявлен имеющимся. Если нельзя подтвердить отсутствие
напряжения, допуск не выдавать.
