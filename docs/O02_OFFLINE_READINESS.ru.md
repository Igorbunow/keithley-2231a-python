# O02 — offline readiness: второй источник и аппаратная синхронизация

**Состояние:** `PLANNED / NOT_RUN`. O01 не квалифицирует O02 и не разрешает выходы второго блока питания. Второй физический источник, безопасная общая схема, триггерный интерфейс/MCU-мост и возможность наблюдать независимые временные метки пока **не подтверждены**.

## Разделение целей

1. **O02-A: два независимых PSU** — раздельная идентификация, разные физические порты/серийные идентификаторы, две независимые конфигурации и два раздельных отказоустойчивых OFF. До электрического подключения допускаются только offline-симуляции и read-only инвентаризация (по отдельному разрешению). Совместное подключение выходов, серия/параллель между разными PSU, общий минус и общая земля не подразумеваются.
2. **O02-B: программно последовательный координатор** — запись монотонных временных интервалов host для каждого прибора и причинно-следственных команд. Не заявлять «синхронность» при отсутствии общей инструментальной метки или внешнего триггера. Проверять ложные PASS при stale reading, нарушении порядка, timeout и дрейфе часов, учитывать неопределённость длительности каждого измерения.
3. **O02-C: hardware-trigger** — только после схемы и электрической совместимости подтверждённого MCU-моста/триггера; определить уровень/полярность, изоляцию, буферизацию, защиту земли, проводники и схему отключения. Отдельный preflight и отдельный операторский допуск. Отсутствие оборудования — `NOT_RUN`, не «PASS».

## Минимальные требования перед физическим O02

- Фактически присутствующие модели и два **разных** уникальных serial/physical IDs; независимые транспорты, нет перекрёстных конфигураций.
- Принципиальная электрическая схема (включая допустимые потенциалы выводов, связь земли, отсутствие несанкционированных перемычек), предельные U/I/P/energy каждого PSU, безопасное состояние при reset/boot и доступный ручной OFF каждого.
- Как включать/останавливать оба блока при сбое одного порта: каждая исправная связь должна попытаться обеспечить OFF, а **неопределённая** связь не должна получать повторных SCPI; при невозможности подтвердить оба OFF итог не выше `ABORTED`.
- Два источника должны по отдельности проходить gates идентичности, профиля, физического OFF и ручного разрешения ON; запрещена автоматическая ретрансляция разрешения с первого PSU на второй.
- Offline fault injection до HW: потеря ответа у одного PSU после ON, stuck-ON readback, обмен транспортами, DMM late response, запись CSV неуспешна, отказ дополнительного наблюдателя, возможный разрыв между включением первого и второго. Проверить полные SCPI-трассы и независимые отключения.

**Следующий инженерный шаг:** проектировать O02-A как offline-only двухсеансовую state machine и тесты fault containment. Не писать и не запускать `O02 --execute`, пока не подтверждены состав стенда и отдельная электрическая карточка.
