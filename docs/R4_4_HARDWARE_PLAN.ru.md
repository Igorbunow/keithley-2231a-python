# R4.4 — аппаратная квалификация скалярных запросов и дисплея

**Статус:** R4.4-A — SIM TESTED; R4.4-B OFF-only runner подготовлен,
**HW REVIEWED PASS** для одного реального OFF-only `DISP?=1` на
прошивке `1.04-1.04` (29.10.2026). Полный аудит: `docs/reviews/R4_4_B_DISPLAY_HW_REVIEW_2026-10-29.md`.
Изменение production-драйвера в R4.4-B отсутствует.

## R4.4-B: только `DISP?`, OFF-only

Безопасная последовательность:

1. Сначала `python3 tools/r4_4_display_qualify.py --config config/bench.local.toml`
   (DRY RUN, соединения не открываются).
2. Убедиться на панели: CH1/CH2/CH3 выключены, Output Recall=OFF;
   режим Independent, **все выходные клеммы пусты**, перемычек и DUT нет.
   Другой управляющий процесс отключён.
3. Только после отдельного разрешения оператора: `python3
   tools/r4_4_display_qualify.py --config config/bench.local.toml --execute`.
   Runner требует TTY, два подтверждения перед открытием UART и физическое
   подтверждение OFF после возвращения в LOCAL. Не использует глобальное OFF,
   не устанавливает уставки, не применяет профиль.
4. Сохранить журнал `reports/hardware/..._R44_DISPLAY_OFF/events.jsonl` и
   терминальный вывод. `PASS` runner означает только успешное исполнение
   **ограниченного протокола**, не автоматический статус `HW REVIEWED PASS`.

Разрешённые SCPI-запросы: `*IDN?`, `SYST:ERR?`, `INST:NSEL?`,
`CHAN:OUTP?`, `OUTP:SER?`, `OUTP:PARALLEL?`, `OUTP:TRAC?`, **один** `DISP?`.
Разрешённые служебные записи: `SYST:REM`, `SYST:LOC`, `INST:NSEL 1/2/3`.
`SYST:ERR?` опрашивает/потребляет **очередь ошибок** после каждой валидной
операции. Регистр событий `*ESR?` и другие `:EVEN?` никогда не читаются.
`DISP?=0` также валиден: это **отключение изображения на дисплее**, а не
выключенный выход. В этой фазе измерений `MEAS:POW?` / `FETC:*` нет.

При ошибке, потере UART или некорректном ответе — ABORTED, без reconnect,
повтора, `OUTP 0` и дальнейших SCPI; состояние выходов необходимо
установить физически. `SYST:LOC` отправляется только при полностью
успешных предварительных проверках и достоверном обмене.

## Отдельная будущая фаза R4.4-C: скалярные измерения под нагрузкой

Эта фаза **ещё не реализована и не разрешена**. Для неё необходим

повторной проверкой согласованного профиля, параметрами стенда из одного
`bench.local.toml`, ручными воротами включения, ограничением мощности,
контролем KEL103 и независимого DMM7510, временем/количеством команд и
подтверждённым OFF. Начинать с низкой мощности Independent CH1, без
внешних перемычек, строго в уже квалифицированном диапазоне H03/H04P.

Предусмотреть сравнение `MEAS:POW?` с U×I от Keithley и значениями
KEL103/DMM7510, а также `FETC:VOLT?`, `FETC:CURR?`, `FETC:POW?`.
`FETC` может отдавать устаревшее значение: отдельные последовательные
запросы не доказывают синхронность либо возраст данных. Допуски нужны
до подачи питания. Не переносить автоматически аппаратные H03/H04P/H09/H10
PASS на новые SCPI-запросы.

## R4.4-C — подготовлен отдельный маломощный runner (HW NOT_RUN)

`tools/r4_4_scalar_qualify.py` — **DRY RUN по умолчанию**. Исполняемая
фаза не выполнялась: запуск с `--execute` допускается только после
отдельного просмотра этого инкремента, схемы подключения и тестовых
ограничений, с локальным TTY и поэтапными ручными подтверждениями.

Фактические подключения четырёх приборов, в том числе PSU / KEL103 USB
и DMM7510 TCP, по-прежнему берутся из единого `bench.local.toml`. Для
аппаратного запуска обязательна отдельная секция:

```toml
[qualification.r44_scalar]
voltage_v = 3.30
current_limit_a = 0.150
load_resistance_ohm = 40.0
max_power_w = 0.60
```

Парсер проверяет **точное совпадение** четырёх параметров с утверждённой
рабочей точкой. Более высокие уставки и неполная секция запрещены ещё
до открытия транспорта. CH1: 3,30 В, ограничение 0,150 А, KEL103 CR40 Ω,
расчётно около 0,0825 А / 0,272 Вт; предел подтверждаемой мощности
0,60 Вт. CH2/CH3 физически свободны и программно остаются OFF.

Подключение **при всех выходах OFF**: положительная клемма KEL103 →
CH1+, отрицательная → CH1−. DMM7510 подключается параллельно к CH1
(передние клеммы; режим DCV/10 В). Никаких перемычек CH1/CH2, DUT,
другого владельца SCPI-соединения. Перед запуском проверить выходы
и INPUT KEL OFF, Output Recall OFF, Independent и полярность. Учитывать,
что `DMM7510.configure_voltage(10)` сбрасывает **только DMM7510** (`*RST`),
поэтому его настройки после испытания нельзя считать восстановленными.

Runner сначала проверяет личности приборов и OFF, затем режимы,
конфигурирует DMM/нагрузку, применяет защищённый независимый профиль
через *production* `Keithley2231A`, повторно подтверждает OFF и
только после дополнительного подтверждения разрешает однократное
`CHAN:OUTP 1` для CH1. Затем собирает последовательные показания
`read_channel(1)` (U/I, вычисленная мощность), KEL103 U/I/P, DMM7510 U,
`MEAS:POW?`, три `FETC:*?`. Для каждого источника фиксируются метки
`time.monotonic` (это **не** синхронный захват). `FETC` проверяются на
конечность и предельные величины, но не объявляются свежими даже при
численном совпадении. Значительное расхождение `FETC` сохраняется в
отчёте, а не скрывается и не автоматически считается ошибкой прошивки.

Предварительные допуски: U источника/нагрузки относительно 3,30 В
±0,20 В; U независимых приборов ±0,08 В; I Keithley/KEL ±0,030 А;
P по измерителю источника относительно U×I и P KEL ±0,080 Вт;
максимум U 3,55 В, I 0,165 А, P 0,60 Вт. Это **критерии одного
проверочного сценария**, не общие паспортные точности приборов.
Все допуски зафиксированы до аппаратной подачи питания.

На выходе обязательны независимые отключение/подтверждение CH1–CH3
и KEL103 INPUT OFF, возвращение PSU в LOCAL только после уверенного
успешного отключения, закрытие подключений и финальное физическое
подтверждение. Если любой обмен нарушен — нет auto reconnect/retry
и нет ложного заявления OFF на неподтверждённой линии. При отсутствии
надёжного readback статус `ABORTED/UNKNOWN`, оператор выполняет
физический аварийный останов. Результат runner, даже `PASS`, означает
только `HW NOT_REVIEWED` до аудита оригинального JSONL.

```bash
python3 tools/r4_4_scalar_qualify.py --config config/bench.local.toml
# --execute — только после отдельного допуска на силовой этап:
# python3 tools/r4_4_scalar_qualify.py --config config/bench.local.toml --execute
```
