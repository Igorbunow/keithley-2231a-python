# R5-E4: безопасная аппаратная проверка записи отложенных уставок

**Состояние: SOFTWARE-ONLY; аппаратная квалификация NOT_RUN.**

Цель — подтвердить на Keithley 2231A-30-3 реальную работу `VOLT:TRIG`
и `CURR:TRIG` **для каждого** CH1/CH2/CH3 по отдельности, при всех
физически выключенных выходах. Проверяются запись, обратное чтение,
повторное чтение, восстановление исходных значений, неизменность
активных обычных уставок `VOLT?` / `CURR?` и окончательный OFF.
Это **не** тест события `*TRG`, реального изменения напряжения под
нагрузкой, синхронизации, задержек, coupling или полного диапазона.

## Программная проверка

После применения инкремента и регрессии только dry-run:

```bash
python3 tools/r5_e4_trigger_write_qualify.py --config config/bench.local.toml --channel 1
python3 tools/r5_e4_trigger_write_qualify.py --config config/bench.local.toml --channel 2
python3 tools/r5_e4_trigger_write_qualify.py --config config/bench.local.toml --channel 3
```

Эти вызовы не открывают физический порт, не меняют регистры и не включают
выходы. Не используйте `--execute` до отдельного разрешения после просмотра
программного журнала.

## Физический preflight (для последующего отдельно согласованного этапа)

Все выходы CH1/CH2/CH3 **физически OFF**, клеммы всех каналов пустые.
Нет нагрузки KEL103, мультиметра DMM7510, DUT, перемычек
Series/Parallel/Tracking, внешнего питания или другого владельца UART.
На приборе независимая топология, режимы соединения и таймеры выключены.
Профиль OFF меняет **обычные неактивные** уставки: CH1 3,30 В/0,150 А,
CH2/CH3 1,00 В/0,100 А, с ограничениями 3,50 В для CH1 и 1,50 В для
CH2/CH3. Все эти значения относятся к тестовой защите, а не к пределам
возможностей прибора.

Только на выбранном канале проверяется одна пара:

| Канал | Пробное `VOLT:TRIG` | Пробное `CURR:TRIG` |
| --- | ---: | ---: |
| CH1 | 2,200 В | 0,120 А |
| CH2 | 0,800 В | 0,080 А |
| CH3 | 0,800 В | 0,080 А |

Сначала читаются исходные два регистра, затем производится последовательность
**VOLT write→read, CURR write→read**, повторное чтение обеих уставок,
возврат исходных значений **VOLT write→read, CURR write→read**,
последнее чтение обеих уставок. Итого ровно **4 trigger-write и 10
trigger-query**, без `*TRG`, `INST:COUP`, выхода ON или автоматической
смены канала. Прежние значения восстанавливаются только если они в
ограничениях текущего защитного профиля и сетке уставок.

**ВНИМАНИЕ:** при ошибке после частичной записи триггерные регистры
могут остаться изменёнными. Это запрещает следующий запуск: выполнить
физический OFF, установить, что связь надёжна, отдельно проверить
текущее состояние регистров и согласовать восстановление. Не включать
никакие выходы, не выполнять `*TRG`, не запускать автоматических повторов.
Скрипт не совершает восстановление через недостоверный UART.

## Операторская команда — только после отдельного согласования

```bash
python3 tools/r5_e4_trigger_write_qualify.py \
  --config config/bench.local.toml --channel 1 --execute
```

Один запуск = один канал. После ручных подтверждений, полностью завершённого
OFF и получения нового файла `events.jsonl` независимый аудит:

```bash
python3 tools/audit_r5_e4_trigger_write.py "/реальный/путь/к/events.jsonl"
```

Только `REVIEWABLE_PASS_OFF_ONLY_NOT_TRIGGER_ACTUATION` + анализ физического
SCPI-trace и исходного SHA-256 допускают запись результата как bounded
OFF-only hardware qualification. Не являются разрешением перейти к
следующему каналу без отдельного preflight или включить нагрузку.

## Технические гарантии

* Работа через production-драйвер, не через raw UART; каждая команда в
  фиксированном allowlist и проверяется по `SYST:ERR?`.
* Граница выбора канала: `INST:NSEL?`, OFF всех трёх выходов на каждом
  важном переходе; невозможность включения выхода после staging в сессии.
* Readback и `verify_profile()` на каждой фазе. Завершающая запись
  `OUTP 0`, запросы `CHAN:OUTP?` на всех трёх каналах, `SYST:LOC`,
  физическое подтверждение.
* Исходный JSONL не перезаписывается; аудит сверяет оригинальные команды,
  ответы, порядок, таймстемпы, хеши, запреты и все четыре записи.
* Если порт/ответ недостоверны — STOP и **никакого повторного SCPI**.
